# 赌石开发计划

赌坊新增第四个玩法「赌石」：花灵石 / 药材 / 矿石买原石，当场切开，开出数量不等的玄铁。
目的：给玄铁一条「花资源就能拿、但带运气」的主力来源（玄铁缺口见宗门 11~15 级、炼器、祭炼）。

金额一律是**最小单位**（1 展示单位 = 1000 最小单位）。文中「个」「灵石」都指展示单位。

---

## 1. 产品规则（已和产品确认，不要改）

### 1.1 入口与解锁

- 赌坊玩法列表新增「赌石」，与论道赌局 / 天机轮 / 灵兽竞逐并列。
- 解锁：与赌坊同一门槛（`GAMBLING_UNLOCK_SECT_LEVEL` = 宗门 2 级），复用 `gamblingUnlockBlockedReason`。
- **占赌坊每日次数**：每切一块算 1 次（连切 10 块算 10 次），与论道 / 天机轮 / 灵兽竞逐共用每天 `DEBATE_DAILY_LIMIT`（50）次；剩余次数不够时整批拒绝（`DAILY_LIMIT`）。

### 1.2 原石档位与概率表

四档，每档四种结果，开出的玄铁数量**固定**（不是区间）。概率用基点（10000 = 100%）。

| 档位 id | 名称 | 价格（灵石） | 宗门门槛 | 垮了 | 小涨 | 大涨 | 天价 | 期望（个） |
|---|---|---|---|---|---|---|---|---|
| `gravel` | 碎石 | 150 | 2 | 4000 / 0 | 4600 / 1 | 1200 / 3 | 200 / 10 | 1.02 |
| `mountain` | 山料 | 500 | 2 | 3500 / 0 | 4500 / 3 | 1700 / 10 | 300 / 40 | 4.25 |
| `oldPit` | 老坑料 | 2000 | 2 | 3000 / 0 | 4500 / 12 | 2100 / 25 | 400 / 160 | 17.05 |
| `meteor` | 天外陨石 | 10000 | 6 | 2500 / 0 | 4600 / 50 | 2500 / 110 | 400 / 800 | 82.5 |

格式：`概率基点 / 玄铁个数`。每行四个概率加起来必须正好 10000。
「天价」= 每档最大奖（碎石 10 / 山料 40 / 老坑料 160 / 天外陨石 800）。

结果 id：`bust`（垮了）/ `small`（小涨）/ `big`（大涨）/ `jackpot`（天价）。

### 1.3 支付

- 三种支付方式：`spiritStone` / `herb` / `ore`。
- 灵石：扣 `价格 × 1000` 最小单位。
- 药材 / 矿石：按坊市**卖出价**折算（2 材料 = 1 灵石），扣 `价格 × 1000 × 1000 / SHOP_SELL_PRICE` 最小单位
  （必须从 `shop.ts` 的 `SHOP_SELL_PRICE` 推导，不要写死 2）。例：碎石用矿石付 = 300 矿石 = 300000 最小单位。
- 不能按坊市买入价折算（那样「灵石买材料 → 材料付款」比直接付灵石便宜，能套利）。
- 余额不够：`requireResource` 抛 `INSUFFICIENT_RESOURCE`（自带缺少数量）。

### 1.4 切石与连切

- 一次请求切 `count` 块，`count` 只能是 `1` 或 `10`（「切石」与「连切 10 块」两个按钮）。
- 总价 = 单价 × count；每块**独立**抽一次结果，结果逐块累加。
- 玄铁容量：**剩余容量装不下一块该档的天价**时拒绝（`CAPACITY_FULL`），连切 10 块也只看这一块；
  放行后整批照常入账，可以顶过容量（玄铁没有自然产出，没有副作用）。
  details 给 `resourceId: 'xuantie'`、`capacity`、`balance`、`room`（room = `floor((capacity - balance) / (天价 × 1000))`）。
  文案：`玄铁库存快满了（装不下一块${档位名}的天价 N 个）`。
- 宗门等级不够该档门槛：`INVALID_STATUS`，文案 `天外陨石需要宗门 6 级`。
- 赌坊未解锁：`INVALID_STATUS`，文案与赌坊相同（`requireGamblingUnlocked`）。

### 1.5 隐藏保底

- 按「宗门 + 档位」记**连续垮了**的次数（新表，见 3.1）。
- 抽每一块之前：如果连续垮了次数 ≥ `STONE_PITY_BUSTS`（= 10），这一块从「小涨 / 大涨 / 天价」三项里按它们原来的概率**重新归一**抽（即去掉垮了）。
- 开出 `bust`：次数 + 1（代码里夹到上限 `STONE_PITY_BUSTS`，表里 CHECK 只写下限）；开出其他任何结果：次数清零。
- 连切 10 块时次数逐块推进（第 3 块触发保底后清零，第 4 块起重新计）。
- 保底不进任何接口返回、界面、日志（与祭炼的 `equipment_refine_fails` 同一做法）。

### 1.6 全服播报

- 开出 `jackpot` 时，每块各播一条（连切里开出 2 块天价就播 2 条）：
  `【赌石】${宗门名}切开一块${档位名}，开出天价玄铁 ×${个数}！`
- 走 `broadcastWorldBoss(db, content, now)`（失败不影响主流程，必须 await，放在 commit 之后）。

### 1.7 赌石记录

- 每次请求写一行**赌坊记录**（`dao_debate_log`，与天机轮 / 灵兽竞逐同一张表，连切 10 块也只写一行）：
  `bet_mode = 'stone'`、`disciple_name = '赌石'`、`multiplier` = 块数、开出玄铁算 `win` / 全垮算 `lose`；
  `stake_detail` = `{resourceId, amount, tier, tierName, count}`，`reward_detail` = `{type:'resource', resourceId:'xuantie', amount, counts}`。
- 在赌坊玩法列表的「赌坊记录」里查看；战绩净灵石把灵石付款的花费算进去（与天机轮同一口径）。

## 2. 代码结构（照着现有写法做）

### 2.1 新规则文件 `apps/server/src/modules/game/stoneGamble.ts`

纯定义 + 纯函数，不读库、不取时间，随机源用参数注入（参照 `tower.ts` / `gambling.ts` 文件头的写法）。内容：

- `STONE_TIERS`：上面 1.2 的表（id、name、price（展示单位）、minSectLevel、outcomes: `{ id, name, chanceBp, xuantie }[]`）。
  结果中文名：垮了 / 小涨 / 大涨 / 天价。
- `STONE_PITY_BUSTS = 10`、`STONE_BATCH_COUNTS = [1, 10] as const`、`STONE_PAY_RESOURCES = ['spiritStone', 'herb', 'ore'] as const`。
- `findStoneTier(id)`、`stoneTierBlockedReason(tier, sectLevel)`（够等级返回 null）。
- `stoneCostUnits(tier, payResource, count)`：按 1.3 算最小单位整数。
- `stoneTopPrize(tier)`：天价个数。
- `stoneExpectedXuantie(tier)`：期望（展示单位，可以是小数，只用于展示和测试）。
- `rollStone(tier, busts, random)`：按 1.5 抽一块，返回结果 id；`random` 是 `() => number`。
- `nextStoneBusts(busts, outcomeId)`：按 1.5 推进次数。
- `cutStones(tier, count, busts, random)`：逐块调用上面两个函数，返回
  `{ outcomes: OutcomeId[], counts: Record<OutcomeId, number>, xuantie: number /* 展示单位 */, nextBusts: number }`。

### 2.2 迁移 `migrations/0046_stone_gamble.sql`

文件头注释格式照 `migrations/0044_equipment_refine.sql`。

```
stone_gamble_busts(sect_id TEXT NOT NULL, tier TEXT NOT NULL, busts INTEGER NOT NULL DEFAULT 0 CHECK (busts >= 0),
                   updated_at INTEGER NOT NULL, PRIMARY KEY (sect_id, tier))

stone_gamble_log(id TEXT PRIMARY KEY, sect_id TEXT NOT NULL, tier TEXT NOT NULL,
                 count INTEGER NOT NULL CHECK (count >= 1), pay_resource TEXT NOT NULL,
                 cost INTEGER NOT NULL CHECK (cost >= 0), xuantie INTEGER NOT NULL CHECK (xuantie >= 0),
                 bust_count INTEGER NOT NULL, small_count INTEGER NOT NULL, big_count INTEGER NOT NULL,
                 jackpot_count INTEGER NOT NULL, created_at INTEGER NOT NULL)
索引：(sect_id, created_at DESC)
```

`cost` / `xuantie` 存最小单位。sect_id 不建 CASCADE（同 0042 / 0044）。

### 2.3 Repository（`repository.ts`）

照 `findRefineFails` / `upsertRefineFailsStatement`（约 3132、3219 行）新增：

- `StoneGambleRepository`（或挂在已有仓储类上）：`findBusts(sectId, tier): Promise<number>`、`listRecent(sectId, limit)`。
- `upsertStoneBustsStatement(sectId, tier, busts, now)`、`insertStoneGambleLogStatement({...})`。

### 2.4 Service（`service.ts`）

新增 `stoneGamble(db, userId, tierId, payResource, count, now)`，**完全照 `refineEquipment`（约 5733 行）的写法**：

1. `const draft = await draftFor(db, userId, now);`
2. `requireGamblingUnlocked(draft)`；找档位（未知 → `VALIDATION_ERROR`）；`stoneTierBlockedReason` 不为 null → `INVALID_STATUS`。
3. 容量校验（1.4），用 `draft.resourceCapacityOf('xuantie')` / `draft.balanceOf('xuantie')`，写法照 `shopBuy`。
4. `draft.requireResource(payResource, stoneCostUnits(...))`。
5. 读保底次数 → `cutStones(tier, count, busts, Math.random)`。
6. `draft.addResource('xuantie', xuantie * 1000)`（xuantie > 0 时）；次数变了才 `draft.addStatement(upsertStoneBustsStatement(...))`；
   `draft.addStatement(insertStoneGambleLogStatement(...))`。
7. `await draft.commit();`
8. commit 之后逐个天价播报（1.6）。
9. 返回 `{ state: draft.view(), result }`，result 见 2.6。

新增 `listStoneGambleHistory(db, userId)`：只读，最近 20 条，照 `listDebateHistory` 的取宗门方式。

### 2.5 Schema / 路由

- `schema.ts`：`stoneGambleRequestSchema = z.strictObject({ tier: z.enum([...4 个 id]), payResource: z.enum(STONE_PAY_RESOURCES), count: z.union([z.literal(1), z.literal(10)]) })`。
  tier 的 enum 从 `STONE_TIERS` 推导或写一个 `STONE_TIER_IDS` 常量。
- `routes.ts`：
  - `POST /game/stone-gamble` → `respondOk(c, { state, result })`（照 `/game/shop-buy`）。
  - `GET /game/stone-gamble/history` → `respondOk(c, { entries })`（照 `/game/debate-history`）。

### 2.6 视图（`view.ts`）

- `SectStateView.gambling` 新增 `stones: StoneGambleView | null`（赌坊未解锁时 null），在 `gamblingView` 里构造：
  ```
  StoneGambleView {
    materialPerStone: number;            // 1 灵石折几个材料 = 1000 / SHOP_SELL_PRICE（= 2）
    tiers: {
      id, name,
      price: number;                     // 灵石，展示单位
      minSectLevel: number;
      unlocked: boolean;                 // 宗门等级够不够
      blockedReason: string | null;
      expectedXuantie: number;           // 展示单位，保留两位小数
      topPrize: number;                  // 展示单位
      outcomes: { id, name, chanceBp, xuantie }[];   // xuantie 展示单位
    }[];
  }
  ```
- `StoneGambleResultView { tier, tierName, count, payResource, cost /* 最小单位 */, xuantie /* 最小单位 */, outcomes: OutcomeId[], counts: Record<OutcomeId, number>, message }`。
  message 例：`切开 10 块山料，开出玄铁 ×52（天价 1 块、大涨 2 块、小涨 4 块、垮了 3 块）`；单块：`切开一块山料，大涨！开出玄铁 ×10`。
- `StoneGambleHistoryEntryView { id, tier, tierName, count, payResource, cost, xuantie, counts, createdAt }`。

- 新组件 `apps/web/src/components/StoneGambleDialog.vue`，**结构照 `SpiritBeastRaceDialog.vue`**：自己调接口，emit `state-update` / `notify` / `back`。内容：

## 3. 测试

### 3.1 规则测试 `tests/game/stone-gamble-rules.test.ts`

- 每档四个概率加起来 = 10000；天价 = 该档最大的 xuantie；`stoneExpectedXuantie` 与 1.2 表一致（1.02 / 4.25 / 17.05 / 82.5）。
- 每档「价格 / 期望」在 110~150 灵石之间（防止以后调参把玄铁调得过便宜）。
- `stoneCostUnits`：灵石 = 价格 × 1000；药材 / 矿石 = 价格 × 2000；count = 10 时 × 10。
- `rollStone`：注入固定 random 覆盖四种结果的边界；busts ≥ 10 时永远不出 bust。
- `nextStoneBusts`：bust +1 且夹到 10；其他结果清零。
- `cutStones`：10 块逐块推进次数；counts 之和 = count；xuantie = 各块之和。

### 3.2 接口测试 `apps/server/test/stone-gamble.test.ts`

建宗门 / 冻结结算 / 改余额的工具函数照 `apps/server/test/shop.test.ts` 抄（宗门等级用 `UPDATE sects SET level = ?`）。

- 1 级宗门 → `INVALID_STATUS`（赌坊未开）；2 级宗门买天外陨石 → `INVALID_STATUS`；6 级可以。
- 灵石 / 药材 / 矿石三种支付各成功一次：扣款正确、玄铁增加 = result.xuantie、写了一条记录。
- 连切 10：扣 10 倍；counts 之和 = 10。
- 余额不足 → `INSUFFICIENT_RESOURCE`，余额不变、没有记录。
- 玄铁容量不够 → `CAPACITY_FULL`，room 正确，余额不变。
- 非法参数（count = 2、未知 tier、payResource = 'xuantie'、多余字段）→ 400。
- 保底：直接把 `stone_gamble_busts` 写成 10，再切一块，结果不是 bust 且次数被清零（读表断言）。
- `GET /game/stone-gamble/history`：按时间倒序、最多 20 条、字段齐全。
- `state.gambling.stones`：2 级宗门有四档，天外陨石 unlocked = false；1 级宗门为 null。
