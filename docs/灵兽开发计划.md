# 灵兽开发计划（一期）

> 目标：增加「野外搜寻 → 削弱收服 → 挑选培养 → 装备搭配」的灵兽玩法，并调整首页功能入口。
>
> 本文整理本次讨论已确认的规则、12 种灵兽的效果草案，以及开发需要补齐的参数。主体仍作为规则与计划来源；实际落地情况、本次采用的数值与后续事项见第 14 节。
>
> 状态说明：「已确认」为本次讨论确定的方向；「数值草案」可在平衡验证后调整；「建议默认」为尚未单独确认的实施建议，不能当作已经确认的需求。

## 1. 一期范围与核心规则（已确认）

- 每名弟子新增一个独立的灵兽槽，每次最多携带一只；每只灵兽同一时间最多归一名弟子携带。
- 灵兽收归宗门管理，可以卸下、换给其他弟子，等级和品质随灵兽保留，不做永久结契。
- 灵兽提供「两项基础属性加成 + 一个固定招牌技能/神通 + 一种固定五行」。不作为独立战斗单位，不单独占行动回合。
- 共 12 种，物种分「灵兽、珍兽、神兽」三档；神兽以幼体形式捕获、培养，幼体是名称与表现，不另增孵化或进化阶段。
- 个体品质为「凡品、灵品、宝品、仙品」，捕获时随机；不设资质、性格、随机技能等额外维度。
- 物种决定五行、属性倾向和技能；品质、等级影响属性和技能数值。触发概率、次数、门槛和免疫等开关机制固定。
- 培养只消耗现有的灵石（`spiritStone`）和灵气（`spiritualEnergy`），不新增培养材料、饲料或捕兽符，不引入独立弟子灵力条。
- 不给灵兽额外配置固定战力或战力百分比。属性进入既有战力/战斗规则，技能与五行在实际结算中生效。
- 不保证同档、同品质、同等级灵兽的面板战力相同；通过属性预算和战斗模拟检查用途与强弱。
- 一期不做繁殖、亲密度、驻守生产、交易、灵兽专属装备、符箓系统、自动捕捉。
- 本玩法与现有赌坊「灵兽竞逐」独立，不改竞猜与赛跑规则。

## 2. 首页布局与秘境入口（已确认）

### 2.1 首页按钮调整

现状与目标如下，主要修改 `apps/web/src/components/SectScreen.vue`：

| 功能 | 当前 | 调整后 |

| 执事堂 | 「宗门」列的大卡片 | 移至「弟子修行」标题栏，位于招贤台与门人调度之间，改为同类紧凑按钮 |
| 功法 | 「市集」列卡片 | 移至「宗门」列，沿用现有卡片样式、收录数量与解锁提示 |

- 删除执事堂原大卡片，移动功法和日课的现有卡片，不保留重复卡片。
- 更新 `.recruit-launch + .dispatch-launch` 等依赖相邻结构的 CSS；窄屏允许按钮组换行，顺序不变。
- 移动入口不改变执事任免、招贤、日课和功法的现有业务规则。弟子详情中的更换主修等上下文入口保留。

### 2.2 秘境探索流程

```text
首页「秘境探索」
  └─ 类型选择弹窗
      ├─ 普通秘境 → 原 ExplorePanel → 原选人、探索、结算/续探流程
      └─ 宠物秘境 → 捕捉区域列表 → 选择区域 → 选择一名弟子 → 搜寻与捕捉
```

- 一级选择项严格使用用户指定的「普通秘境」「宠物秘境」名称；系统内收藏与装备仍称「灵兽」。
- 原普通秘境的数据、次数、奖励、快速探索与交互式探索能力保持原行为，宠物秘境使用独立额度与记录。
- 一级弹窗分别展示两类秘境的进行中状态和可用情况，普通秘境次数用完不能禁用整个入口。
- 普通秘境已有进行中探索时，可以从普通秘境继续；宠物秘境也必须提供继续遭遇的入口。
- 两个分支有明确的返回类型选择操作。关闭弹窗不等于放弃已经开始的探索/捕捉。
- 日课、待办「去继续」、参谋等已明确指向普通秘境的跳转直接进入原分支，避免多一层选择。首页通用秘境入口始终先选类型。
- 灵兽苑作为宠物秘境内的「我的灵兽」管理页/标签，弟子灵兽槽也可直接打开；一期不额外新增需要升级的生产建筑。

## 4. 品质、升级与管理

### 4.1 品质（方向已确认，倍率为数值草案）

| 品质 | 属性倍率草案 | 技能数值倍率草案 |
|---|---|---|
| 凡品 | ×1.0 | ×1.0 |
| 灵品 | ×1.2 | ×1.1 |
| 宝品 | ×1.4 | ×1.2 |
| 仙品 | ×1.6 | ×1.3 |

- 品质不改变物种档次、五行与技能。仙品玄甲龟仍属于灵兽，不变成神兽。
- 技能倍率只放大增伤、回血、护盾、追击加成等数值，不改变触发概率、每场次数、35% 残血门槛、免疫和必定暴击。
- 属性与技能分别计算品质和等级系数，向下取整的时点统一；低数值回血不能因展示取整与结算取整不一致。
- 概率、追击上限、减伤、回血等设置最终安全上限；品质与升级不能造成无限追击、无敌或无限续航。
- 品质首期不提升是建议默认，需与最终升级曲线一起定稿。

### 4.2 升级（资源已确认，曲线待定）

- 直接消耗现有灵石与灵气升级，不新增材料或灵兽经验道具，不依赖喂食。
- 前端展示当前等级、下一级属性/技能变化、两种资源费用及不足原因。
- 等级上限、是否随宗门等级开放上限、成长系数与费用曲线列入待定参数；没有确认前不把任意上限写成既定需求。
- 建议默认升级必定成功，无失败降级；物种不会通过升级自动变成另一种。

### 4.3 灵兽苑与灵兽槽

- 我的灵兽列表可按五行、物种档次、品质、是否装备筛选；展示头像、名称、档次、品质、等级、携带弟子。
- 详情显示立绘、属性、技能、五行关系、升级费用，并提供装备、更换、卸下、锁定、放生。
- 每名弟子详情新增灵兽槽：未装备时显示选择入口，已装备时显示头像、品质、等级、技能摘要和属性来源。
- 装备操作显式处理当前槽已有灵兽、目标灵兽已由他人携带的情况；更换后正确刷新两名弟子的状态。
- 正在外出/捕捉等受占用弟子的换兽、卸兽、培养按统一规则限制，不能绕过出发快照改变当前战斗。
- 灵兽锁定为防误放生措施，不影响正常装备。已装备、锁定或处于活动快照中的灵兽不能直接放生。
- 放生需要确认。是否返还资源、返还数值尚未确认；不默认生成培养材料。
- 驱逐弟子时灵兽回到宗门，保留培养，不随弟子删除。
- 容量上限待定；容量不足必须在搜寻前提示并拦截，不能捕获成功后丢失灵兽或强制扣费。活动期间需为可能捕获的灵兽保留容量。

## 5. 宠物秘境与捕捉流程

### 5.1 区域（建议默认）

建议先做三个难度区域，每区混合五行，不采用只有某个五行才能进入的硬限制：

| 区域名（暂定） | 定位 | 可出现物种 |
|---|---|---|
| 青岚山麓 | 入门捕捉，能获得第一只灵兽 | 五种灵兽 |
| 云雾深谷 | 中期收集，珍兽为主要追求 | 五种灵兽、三尾灵狐、岩甲犀 |
| 太古遗境 | 后期挑战，神兽幼体稀有出现 | 部分灵兽/珍兽、五种神兽幼体 |

- 区域显示宗门/弟子门槛、搜寻费用、可出现图鉴、稀有程度、今日剩余次数。
- 未解锁区域可查看目标和解锁条件；尚未见过的种类可用剪影或未知标记。
- 区域名称、解锁等级、野生强度、物种权重不是已确认数值，实施前按第 13 节定稿。

### 5.2 一次捕捉的操作

1. 选择区域与一名可出战弟子。没有携带灵兽也能出发，解决第一只的获取。
2. 搜寻：服务端扣费、扣搜寻额度，生成并保存本次遭遇；前端显示物种、五行、强度、血量、操作说明。
3. 选择攻击或留手：主人行动，携带灵兽按机制辅助；野生灵兽未倒下时可反击。
4. 选择御兽术收服：根据目标剩余血量、双方境界与弟子幸运计算成功率；失败后目标可能反击或逃跑。
5. 成功：灵兽以 1 级进入宗门灵兽苑，显示品质、属性与技能，可在结束遭遇后装备。
6. 击杀、目标逃跑、弟子战败或主动离开：结束遭遇，释放弟子占用。具体战败受伤和退款规则见待定项。

- 不新增捕兽符，不新增独立弟子灵力条；御兽术是收服操作名称，费用统一使用现有资源体系。
- 留手保护覆盖本次主人伤害、追击、剑气、狐火/离火等所有追加伤害，最低留 1 点目标血量。
- 留手不等于不受反击；普通攻击允许击杀目标，确认文案清楚区分。
- 同一次遭遇刷新、关弹窗再打开、断线重连时保持目标、品质和进度，不重新抽取。
- 所有操作由服务端判定；遭遇设置回合/操作上限、收服尝试上限和过期时间，避免无限尝试及长期占用，具体数值待定。
- 每宗门同时一场捕捉是建议默认；普通秘境与宠物秘境共用弟子占用检查，同一弟子不能同时执行两类活动。
- 普通秘境与捕捉不共用次数；捕捉先不计入既有普通秘境日课，避免无意改变任务完成条件。

### 5.3 幸运与概率

- 幸运作用于「稀有物种遭遇」与「捕获成功」，不影响个体品质抽取。
- 捕获率由「物种档次基础难度 + 削弱收益 + 境界修正 + 幸运修正」形成，设置上限与下限；不是点一下直接按幸运抽奖。
- 建议以现有幸运 50 为中性点，在附近做有限修正，概率公式与区域物种权重由服务端统一计算并下发预览。
- 基础幸运与携带灵兽/装备幸运的计入口径必须固定并展示；建议使用出发时的战斗幸运快照，并对捕捉用途单独设有效上限。
- 稀有遭遇加成使用归一化权重，不能只增加某种概率而使总概率超过 100%。
- 个体品质与野生强度在遭遇创建时固定，捕获重试不能重抽品质；前端是否提前揭示品质需要定稿。
- 区域与境界硬门槛不能被高幸运绕过；幸运不能让未开放的神兽进入抽取池。

## 6. 五行与战斗结算

### 6.1 克制规则（已确认）

```text
金克木 → 木克土 → 土克水 → 水克火 → 火克金
```

| 关系 | 伤害倍率 |
|---|---|
| 攻击方克制目标 | ×1.15 |
| 攻击方被目标克制 | ×0.85 |
| 同五行或无克制关系 | ×1.00 |
| 任意一方无五行 | ×1.00 |

- 弟子携带什么灵兽，就具有对应战斗五行；未携带为无五行，不修改功法五行或另造弟子灵根系统。
- 野生灵兽具有对应固定五行。镇妖塔妖物与 Boss 需要单独配置五行并在出战前可见，不能前端自行按名称猜测。
- 每段直接伤害只应用一次五行倍率。狐火等以已经应用倍率的基础伤害求追加部分时，不再重复乘同一倍率。
- 五行不影响回血、护盾生成值与捕获概率本身；通过战斗削弱间接影响捕捉。

### 6.2 与功法协作

- 参考 `techniques.ts`，灵兽用独立修正对象与功法共同参与结算，不覆盖弟子主修功法。
- 首击、暴击、追击、回合回血、残血增伤沿用现有概念；新增护盾单独记录剩余值，优先吸收对应直接伤害。
- 剑气、狐火、离火等追加伤害彼此不触发，不再次触发暴击或追击，不把追加伤害叠进其他追加效果的计算基数。
- 「每次出手」包含主人实际发生的普通出手和追击；每次符合条件的出手最多判定一次灵兽追加效果。
- 首次必暴是一个布尔效果，白虎与一剑破甲不重复暴击；暴击倍率加成正常参与。血量归零后不能靠回血或护盾复活。
- 蛟龙提高追击概率与上限，不增加每次行动的最大出手次数；最大出手次数仍由基础规则或流云身法决定。
- 技能与功法的同类增益明确采用加法还是乘法；写入纯规则表，不在多个调用处各写一版。减伤/追击/回血等最终上限统一。
- 普通属性加成不随五行改变，换五行不修改已捕获灵兽的品质或等级。

### 6.3 共享血条与车轮战

- 镇妖塔现为队伍共享血条。主人血量份额按自身贡献的最大血量计算，不把单只灵兽的治疗、护盾或减伤直接扩成全队收益。
- 主动攻击按该弟子的五行结算；敌方攻击拆分为成员份额，分别结算五行与减伤后汇总。
- 全队无灵兽时分摊与取整结果必须保持原值，不能因新的分摊算法改变旧战斗。
- 残血判定使用队伍当前血量比例；首次承伤状态每名携带者单独记录。
- 车轮战需明确「每场一次」与「每轮一次」：建议沿用当前每场单挑重置功法触发计数的方式，灵兽触发计数同样重置，剩余血量沿用原规则；结束时不携带上场剩余护盾进入下一场。此项纳入平衡验证。

## 7. 生效范围与老玩法兼容

| 场景 | 一期接入方式 |
|---|---|
| 宠物秘境 | 属性、技能、五行完整生效；支持留手保护与收服状态机 |
| 镇妖塔、胜率预估 | 完整接入；预估与真实挑战必须使用同一规则，保留共享血条口径 |
| 宗门大比与复用单挑引擎的战斗 | 接入 `simulateArenaDuel`，包括技能、五行与护盾，使用实际对战快照 |
| 世界 Boss（手动/自动讨伐） | 属性、五行与可直接结算的输出效果接入同一路径；回合、生存类技能需要单独映射表 |
| 普通秘境、宗门挑战等旧式概率/总战力结算 | 属性按既有战力口径参与；非逐回合效果不能假装完整生效，是否扩展模拟或采用专用映射需定稿 |
| 弟子详情、选人列表、天骄榜等战力展示 | 使用与服务端实际战力一致的属性加成，展示灵兽来源；不额外加固定战力 |
| 修炼、生产、执事、定时历练、赌坊 | 不因新增灵兽槽自动获得灵兽收益，沿用各玩法原本的属性口径 |

- 当前 `realms.ts/discipleCombatPower` 只按攻击、防御、身法加权，幸运影响暴击，体魄影响血量，二者不直接增加面板战力。计划按真实代码实现，不承诺「所有属性都直接涨战力」。
- 灵兽增加攻击/防御/身法时自然影响面板；幸运/体魄和技能价值通过战斗、血量与预估体现。不能为凑齐面板涨幅偷偷给生存型灵兽补战力百分比。
- `gear_power_bp` 仍只属于原装备；灵兽属性、品质倍率和技能不写入此列，原装备战力规则不受影响。
- 世界 Boss 不是回合制，不能直接运行「回合回血、首次残血」；必须在上线前列出 12 种对应的 Boss 伤害/受伤风险映射或明确未生效项，并在说明里展示，不能静默忽略。
- Boss 血量动态预估不因为计入玩家新加成同步抬高，避免抵消培养收益。
- 历史战报、已结算大比和已生成快照不能按当前新灵兽状态重算。没有灵兽的旧账号保持原行为。

### 8.2 数据表（结构建议）

|---|---|

- 同一宗门、同一弟子只能装备一只；使用唯一索引保证 `disciple_id` 非空时唯一，并在提交时验证宗门归属。

### 8.3 并发与占用

- 沿用当前 `SectDraft` + `mutation_guards` + 单次 D1 batch 的提交方式；新增捕捉与灵兽写操作的专用守卫，不只在内存里检查。
- 一次搜寻的费用、次数、容量占位、弟子占用、遭遇与图鉴发现记录同批提交。
- 一次操作的旧 session version、资源变化、血量/尝试次数、终态、捕获入库与图鉴捕获记录同批提交。
- 收服成功最多创建一只个体；重复请求、并发双击或网络重试不能重复扣费、重抽品质或重复入库。使用操作幂等键与版本校验，重复请求返回已提交结果。
- 升级、装备、换人、卸下、放生同样校验版本、归属和占用。两名弟子换兽的提交具备原子性。
- 在 `requireCanFight` 及普通探索/历练/执事/坐镇/驱逐等相关入口加入捕捉占用校验；不能只在新页面隐藏按钮。
- 出发时拦截已有冲突活动；捕捉期间不能通过升级、更换功法/装备/灵兽、驱逐或调度绕过快照与占用规则。
- 过期活动在读取/操作时惰性结算并释放，不需要为每只灵兽新增定时任务。

## 12. 验收与验证

### 12.1 页面验收

- 执事堂仅在目标标题栏出现，顺序为招贤台/执事堂/门人调度，按钮风格一致，桌面与窄屏不重叠。
- 功法在宗门列，日课在出战列；原角标、进度、红点、任命和领取均可用。
- 秘境先选择类型，普通分支完整进入原页，宠物分支可选区域；可返回、关闭、恢复。
- 无第一只灵兽也能捕捉；已有灵兽协助后可捕获、收容、升级、换人装备。
- 图鉴放生后保留进度；已装备/锁定个体不会误放生；容量不足时不会吞捕获结果。

### 12.2 有意义的规则与集成测试

- 12 种定义、品质/等级缩放、固定触发规则与最终上限。
- 完整五行矩阵：5×5、无属性中性、方向不反转、每段只乘一次。
- 留手覆盖剑气、追击和追加伤害，最终保留 1 血；普通攻击可击杀。
- 幸运对遭遇/捕获的单调性和上下界；高幸运不影响品质、不绕过区域门槛。
- 回血不超最大血量、不复活；护盾优先吸收并且仅触发一次；首击与必暴不会重复。
- 功法组合：白虎+一剑破甲、朱雀/灵狐+太乙、蛟龙+流云、麒麟+血身、龙龟+背水。
- 同一次遭遇断线/刷新不重抽；双击/重试不重复扣费、扣次数或发灵兽；终态不能再操作。
- 升级、换人、放生、容量与捕捉并发时无部分写入；跨宗门 ID 不能操作。
- 捕捉占用覆盖原有出战/历练/执事/坐镇/驱逐入口；过期或结束后及时释放。
- 无灵兽时原战斗结果、随机数消耗顺序与原普通秘境逻辑保持兼容；历史战报仍可读。
- 服务端预估和真实战斗用相同加成；Boss 手动/自动走同一灵兽映射。

### 12.3 平衡与项目检查

- 在同境界、同品质、同等级下对比 12 种灵兽，并覆盖不同功法、五行和战斗时长。使用固定种子、足够样本，检查输出/生存用途与最强组合。
- 检查火土中期珍兽优势是否挤压其他五行；神兽是否有明显成长价值，品质是否仍有捕捉意义。
- 检查高幸运与高战力捕兽弟子的取舍，以及搜寻、培养消耗与现有灵石/灵气经济的关系。
- 实施完成运行相关单元/服务端集成回归，以及仓库 `npm run typecheck`、`npm run test:unit`、`npm run build`。本次仅文档变更不运行游戏测试。
