# 拍卖行开发计划

> 宗门之间的物品交易：给仙品装备、洗髓丹、玄铁 / 神木等稀缺物品一个流通渠道，同时用手续费回收灵石。

## 1. 规则

| 项 | 规则 |
|---|---|
| 开放 | 宗门 3 级（买卖都要） |
| 可交易 | 背包里的装备（穿着的要先卸下）、丹药（全部配方）、玄铁、神木。药材 / 矿石走坊市，功勋不可交易 |
| 上架 | 物品立刻托管（装备行删除、快照存进拍卖单；丹药 / 材料扣库存）；竞价 24 小时；可选一口价（≥ 起拍价） |
| 数量 | 装备一单 1 件；丹药 1～99 颗；材料 1～999 个；每个宗门同时最多 10 单在拍 |
| 最低起拍价 | 物品成本 × 20%：装备按炼器成本、丹药按炼丹成本（玄铁 / 神木按 50 灵石折算），玄铁 / 神木每个 10 灵石。凡品 46、灵品 150、宝品 380、仙品 980；聚气丹 10、洗髓丹 150 |
| 出价 | 灵石当场冻结；被超价时原数退回；下一口 ≥ 当前价 × 1.05（向上取整、至少 +1）；卖家不能出价；领先者不能再加；出价 ≥ 一口价时要求直接一口价 |
| 一口价 | 当场成交、物品当场到手（装备需背包有空位）；前一个领先者退回；卖家所得当场入账 |
| 下架 | 只有还没人出价时可以，物品当场退回；大厅与「我的拍卖」都有按钮 |
| 同网络 | 上架时记下卖家网络标识的哈希（IPv4 整个地址 / IPv6 前 64 位，不存明文）；买家网络相同时不能出价、一口价（迁移 0041） |
| 到期 | 定时任务（每 10 分钟）+ 打开面板时顺手结算：有人出价 → 成交，卖家所得入账，买家在「待领取」领；没人出价 → 流拍，卖家在「待领取」领回 |
| 手续费 | 成交价的 10%，从卖家所得里扣，灵石直接销毁 |
| 广播 | 仙品装备成交时全服广播 |

## 2. 实现

- 纯规则：`apps/server/src/modules/game/auction.ts`（最低价、加价、手续费、装备快照）。
- 迁移 `migrations/0040_auction.sql`：`auction_lots`（一行一单，`version` 守卫）、`auction_bids`（出价记录）。
- 服务：`getAuction` / `listAuctionItem` / `bidAuction` / `buyoutAuction` / `cancelAuction` / `claimAuction` / `processAuctions`（定时任务）。
  每个命令一次受保护 batch：本宗快照守卫 + 拍卖单 version 守卫；退回 / 卖家入账对对方余额做相对加法。
- 接口：`GET /game/auction`、`POST /game/auction/{list,bid,buyout,cancel,claim}`。
- sync 的 `state.auction.claimable`：待领取单数（「拍卖行」按钮角标）。
- 前端 `AuctionDialog.vue`：拍卖大厅（分类筛选、排序、出价 / 一口价）、我要上架、我的拍卖（待领取 / 我上架的 / 我出价的）。
  操作栏「市集」组加「拍卖行」。

## 3. 测试

- `tests/game/auction-rules.test.ts`：最低价、加价、手续费、白名单、快照解析。
- `apps/server/test/auction.test.ts`：解锁与最低价、出价冻结 / 超价退回 / 到期成交领取、一口价、流拍领回与撤回、装备（背包满拦截、按快照交付）、丹药。

## 4. 随机游商（0059）

- 云游商人是系统卖家，不创建玩家账号或宗门。拍卖单 `seller_sect_id` 为 NULL、`merchant_visit_id` 非空。
- 首次随机等待 2～6 小时；每次停留 6 小时，离开后随机等待 2～6 小时。定时任务每 10 分钟检查，打开拍卖面板也会检查；不向玩家提供下一次到访时间。
- 每次 8～12 单，约六成为装备，剩余为玄铁 / 神木（两种至少各一单）。所有商品全服共享，刷新不重抽，售罄也不立即补货。
- 装备凡 / 灵 / 宝 / 仙权重为 20 / 35 / 30 / 15；兵器、护甲、法器均可能出现，未祭炼，来源记为 merchant。
- 装备起拍基准为 100 / 350 / 1000 / 2500 灵石，上下随机 10%；一口价为起拍价的 1.8～2.2 倍。材料每单 5～20 个，起拍单价 25～40 灵石，一口价单价 50～75 灵石。
- 成交款全额回收；撤标仍扣 5% 违约金并回收。竞拍到期由买家领取，一口价即时交付；流拍商品撤走，无系统卖家领回流程。
- 到访状态、整批货物和系统公告使用同一受保护事务提交，版本守卫防止并发重复到访。下一次到访从实际出现时间计算，长时间停服不会一次补刷多批。
- 大厅显示游商停留状态、商品标签和卖家筛选；首页显示剩余游商单数。上线公告和每次到访公告都会进入全服聊天。
- `tests/game/auction-merchant-rules.test.ts` 验证商品分布与旧数据迁移；`apps/server/test/auction-merchant.test.ts` 验证并发到访、竞拍、一口价、撤标、到期领取和抢购。
