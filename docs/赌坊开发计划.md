# 赌坊系统开发说明（论道赌局）

版本：v1（第一版可玩闭环）

目标读者：负责直接修改本仓库的开发模型。

## 1. 背景与目标

当前游戏已具备：宗门创建、离线结算、弟子招募/培养/突破、建筑升级、丹药系统、秘境探索、宗门挑战、弟子历练。所有资源存储使用最小单位整数（1 展示单位 = 1000 最小单位，前端 `formatAmount` 会除以 1000）。

下一步加入赌坊系统"论道赌局"，目的：

1. 给灵石和资源一个新的冒险性消耗出口（不像丹药那样稳定回报）。
2. 引入「悟道值」作为新的弟子成长货币：可手动加点到任意属性（不像淬体丹只能补短板）。
3. 给高属性弟子一个"高风险高回报"的属性赌注玩法。
4. 通过 jev Decisions API 让胜负不是简单固定概率，而是基于弟子实际能力的智能判定。

本版本完成后，玩家应该能走通：

```text
宗门达到 2 级
  -> 打开赌坊面板（游戏模式列表，当前只有「论道赌局」）
  -> 选择赌注模式（系统预设灵石 / 自由输入资源 / 属性赌注）
  -> 选择出战弟子
  -> 配置赌注倍率（1x/2x/3x）+ 选择奖励类型
  -> 弟子 vs 虚拟对手，jev 判定胜负
  -> 赢：获得资源/悟道值；输：失去赌注
  -> 在弟子详情面板花悟道值给弟子加属性点
```

## 2. 明确的设计决策

### 2.1 解锁条件

宗门等级 `>= 2`。不依赖建筑。

### 2.2 每日限次

每日 10 次（UTC+8 自然日重置），全宗门共享计数。使用与挑战系统相同的 `debate_date_key` + `debate_count` 模式存储在 `sects` 表。

### 2.3 悟道值系统

- `dao_insight`：弟子当前可用悟道值余额（非负整数）。
- `dao_insight_used`：弟子累计已分配悟道值（非负整数，上限 50）。
- 悟道值加点在弟子详情面板操作：玩家选择目标属性（attack/defense/speed/aptitude/luck/physique 六选一）和分配点数，1 悟道值 = 1 属性点。
- **属性上限 100**：加点后不能超过 100。
- **悟道值总分配上限 50**：每个弟子 `dao_insight_used` 累计不超过 50。
- 悟道值只能通过赌坊获得（本版本），后续可能开放其他渠道。

### 2.4 不做的事情

- 不做异步或排队赌局。
- 不生成真实 NPC 弟子作为对手——对手是虚拟概念，只用 jev 的 noul 问题直接判定胜负概率。
- 不做赌坊历史面板（本版本只有 `dao_debate_log` 记录，不做前端查看）。
- 不做玩家对玩家赌局。
- 不修改 `GameConfigContent`、`GAME_CONFIG_VERSION`、`GAME_CONFIG_PAYLOAD_HASH`。
- 不引入 Vue Router 或 Pinia。

## 3. 三种赌注模式

### 3.1 模式 A：系统预设灵石（可选资源或悟道值奖励）

玩家从固定档位选择，可以选择"赢灵石"或"赢悟道值"作为奖励。

| 倍率 | 赌注（灵石） | 赢 → 灵石奖励 | 赢 → 悟道值 | 输 → 损失 |
|------|-------------|--------------|------------|----------|
| 1x   | 100000      | 180000       | 1          | -100000  |
| 2x   | 200000      | 360000       | 2          | -200000  |
| 3x   | 300000      | 540000       | 3          | -300000  |

注意：灵石数值是最小单位。100000 最小单位 = 展示 100。

### 3.2 模式 B：自由输入资源（只能赢资源，不能赢悟道值）

玩家输入灵石/药材/矿石中任一种资源的数量，选择倍率。

| 倍率 | 赌注 | 赢 → 奖励 | 输 → 损失 |
|------|------|----------|----------|
| 1x   | N    | N × 1.8  | -N       |
| 2x   | N×2  | N×2 × 1.8| -N×2    |
| 3x   | N×3  | N×3 × 1.8| -N×3    |

- 输入最小值 10000（展示 10），无上限（但必须有足够余额）。
- 可选资源：`spiritStone`（灵石）、`herb`（药材）、`ore`（矿石）。

### 3.3 模式 C：属性赌注（只能赢悟道值）

玩家选择一个弟子的一个属性（attack/defense/speed/aptitude/luck/physique），以属性点作为赌注。

| 倍率 | 赌注（属性点） | 赢 → 悟道值 | 输 → 损失 |
|------|--------------|------------|----------|
| 1x   | 1            | 2          | -1 属性点 |
| 2x   | 2            | 3          | -2 属性点 |
| 3x   | 3            | 4          | -3 属性点 |

- 属性扣减后**没有下限**，可以扣到 0。
- 选择的属性当前值必须 >= 赌注点数。

## 4. jev Decisions API 集成

### 4.1 状态文本构造

```
论道赌局：{弟子名}（{境界名}{阶段名}，攻击{attack} 防御{defense} 速度{speed} 资质{aptitude} 幸运{luck} 体魄{physique}，战力{combatPower}，天赋：{talentName}）
赌注倍率：{multiplier}x（{multiplierHint}）
```

其中 `multiplierHint` 根据倍率：
- 1x → `"势均力敌的对手"`
- 2x → `"略强于己的对手"`
- 3x → `"远超己身的对手"`

### 4.2 问题定义

只发一个 `noul` 类型的问题：

```typescript
{
  win: {
    type: 'noul' as const,
    criteria: '该弟子在论道中战胜对手的概率。考虑弟子综合实力与对手强度差距。',
  }
}
```

jev 返回 `{ win: { noul: number } }`，即胜率（0~1）。

### 4.3 使用胜率

拿到胜率 `p` 后，`Math.random() < p` 就是本次结果。

### 4.4 降级策略

如果 `env.OPENROUTER_API_KEY` 不存在或 `decide()` 调用失败：

- 1x → 50% 胜率
- 2x → 40% 胜率
- 3x → 30% 胜率

### 4.5 幸运属性侦查效果

弟子 `luck >= 70` 时，结果中 `revealedAttributes` 返回 1 个对手属性提示；`luck >= 85` 时返回 2 个。这只是给玩家看的额外信息（"对手攻击力较高"之类的文案），不影响胜负判定。

侦查文案由服务端根据弟子属性和倍率生成，不依赖 jev。生成规则：随机选 1~2 个属性，根据弟子对应属性值和倍率给出提示（如"对手速度远超你"或"对手体魄不如你"）。

## 7. 后端 service 函数

在 `apps/server/src/modules/game/service.ts` 中新增：

### 7.1 `daoDebate` — 论道主函数

```typescript
export async function daoDebate(
  db: D1Database,
  userId: string,
  input: {
    discipleId: string;
    betMode: BetMode;
    multiplier: Multiplier;
    // 模式 A 用
    rewardType?: 'resource' | 'insight';
    // 模式 B 用
    resourceId?: string;
    amount?: number;
    // 模式 C 用
    attribute?: BettableAttribute;
  },
  now: number,
  env: Env,
): Promise<{ state: SectStateView; result: DaoDebateResultView }>
```

逻辑流程：

1. `draftFor(db, userId, now)` — 加载快照、结算经济。
2. 校验解锁：`requireGamblingUnlocked(draft)`。
3. 校验每日次数：读 `debate_date_key` / `debate_count`，UTC+8 日期键归一。
4. `draft.discipleById(discipleId)` — 校验弟子归属。
5. `requireNotAway(draft, disciple, 'action')` — 不能在历练中。
6. 按 `betMode` 分支校验赌注：
   - **preset_spirit_stone**：灵石余额 >= `PRESET_STAKES[multiplier]`，rewardType 必须是 `'resource'` 或 `'insight'`。
   - **free_resource**：resourceId 在白名单内，amount >= `FREE_BET_MIN`，余额 >= amount × multiplier。
   - **attribute**：attribute 在白名单内，弟子当前属性值 >= `ATTRIBUTE_STAKES[multiplier]`。
7. 调用 jev 获取胜率（或降级）：
   - 构造 `debateStateText(disciple, multiplier)`
   - `decide(apiKey, stateText, { win: { type: 'noul', criteria: '...' } })`
   - 胜率 = `normalizeProbability(answer.win.noul)`
   - 失败降级：`DEGRADED_WIN_RATES[multiplier] / 10000`
8. `Math.random() < winProb` → `result = 'win' | 'lose'`。
9. 按结果执行写入：
   - **赢**：发奖（资源增加或悟道值增加）。
   - **输**：扣赌注（资源扣减或属性扣减）。
   - 写论道记录。
   - 更新论道计数。
10. `draft.commit()` → 一次 D1 batch。
11. 生成侦查文案 `revealHints`。
12. 返回 `{ state: draft.view(), result: { ... } }`。

### 7.2 `allocateDaoInsight` — 悟道值加点

```typescript
export async function allocateDaoInsight(
  db: D1Database,
  userId: string,
  discipleId: string,
  attribute: BettableAttribute,
  points: number,
  now: number,
): Promise<{ state: SectStateView; outcome: InsightAllocateOutcome }>
```

逻辑：

1. `draftFor(db, userId, now)` — 加载快照、结算。
2. `draft.discipleById(discipleId)` — 校验归属。
3. 校验 `points >= 1`。
4. 校验 `disciple.dao_insight >= points`（余额够）。
5. 校验 `disciple.dao_insight_used + points <= DAO_INSIGHT_CAP`（不超 50 上限）。
6. 校验 `disciple[attribute] + points <= 100`（属性不超 100）。
7. 执行写入：`dao_insight -= points`、`dao_insight_used += points`、`attribute += points`。
8. `draft.commit()`。
9. 返回。

## 14. 边界条件与注意事项

1. **资源操作用整数**：`FREE_BET_WIN_MULTIPLIER = 1.8`，计算后 `Math.floor()` 截断到整数。
2. **属性值范围 0~100**：属性赌注输了扣到 0 是允许的（用户确认过"废人就废人"）。
3. **悟道值加点属性范围 1~100**：加点后不超过 100，当前属性值加上 points 必须 <= 100。
4. **并发安全**：使用 `mutation_guards` 快照守卫（与炼丹/挑战同一模式）。赌坊的快照守卫需要核对：宗门行（debate_date_key + debate_count）、资源余额（资源赌注时）、弟子行（属性赌注时核对属性值）。
5. **历练中弟子不能参赌**：使用 `requireNotAway` 校验。
6. **受伤弟子不能参赌**：检查 `injured_until > now`。
7. **幸运侦查是纯文案**：不影响胜负计算，不调用 jev。
