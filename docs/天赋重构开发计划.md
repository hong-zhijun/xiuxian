# 天赋重构开发计划

> 目标：天赋从「4 个无关痛痒的 +20%」改成 **11 个、分 4 类、随境界变强** 的专精系统；
> 新增 **洗髓丹**（洗天赋、二选一、每人限 10 次）与 **执事堂**（宗门类天赋任执事才生效，执事不能出战）。

---

## 0. 原则与边界

- 天赋定义仍是**代码常量**（新文件 `apps/server/src/modules/game/talents.ts`），不进 game-config，不改配置哈希。
- 弟子表 `talent` 列只存 id：**保留现有 4 个 id**（`herbGathering` / `mining` / `cultivation` / `combat`），只改名字与效果；老弟子不迁移数据。
- 所有数值、文案、天赋表都由服务端下发，前端只渲染。
- 不做：天赋品级、「狂战」类高风险天赋、天赋影响论道 / 综合评分。

## 1. 天赋表

### 1.1 境界系数

天赋强度 = 基础值 × 境界系数（按弟子**当前境界**，同境界三个阶段相同）：

| 境界 | 炼气 | 筑基 | 金丹 | 元婴 | 化神 |
|---|---|---|---|---|---|
| 系数 | ×1 | ×1.25 | ×1.5 | ×2 | ×2.5 |

`talentBonusBp(talentId, realmId) = floor(baseBp × 系数)`，基点（10000 = 100%）。

### 1.2 十一个天赋

| 类别 | id | 名称 | 基础值 | 炼气 → 化神 | 生效条件与效果 |
|---|---|---|---|---|---|
| 产出 | `herbGathering` | 灵植 | 2000 | +20% → +50% | 在**药园**岗位时自身产出提高；历练采集的药材同样提高 |
| 产出 | `mining` | 矿脉 | 2000 | +20% → +50% | 在**采矿**岗位时自身产出提高；历练采集的矿石同样提高 |
| 产出 | `spiritGathering`（新） | 聚灵 | 2000 | +20% → +50% | 在**采灵 / 吐纳**岗位时自身产出提高；历练获得的灵石同样提高 |
| 修行 | `cultivation` | 悟道 | 1600 | +16% → +40% | 修炼岗位修炼速度提高；历练修为同样提高 |
| 修行 | `pillAffinity`（新） | 丹心 | 2000 | +20% → +50% | 服用聚气丹时每颗修为提高 |
| 战斗 | `combat` | 战意 | 1000 | +10% → +25% | 战力提高（讨伐、秘境、切磋、守擂） |
| 战斗 | `critical`（新） | 会心 | 6000 | +60% → +150% | 讨伐**暴击**时，该弟子的伤害额外提高 |
| 战斗 | `ironBody`（新） | 铁骨 | 2000 | −20% → −50% | 讨伐时自身受伤、重伤概率降低 |
| 宗门 | `forging`（新） | 炼器 | 400 | +4% → +10% | **任炼器执事**时：全宗炼器成功率提高 |
| 宗门 | `alchemy`（新） | 丹道 | 800 | −8% → −20% | **任丹房执事**时：全宗炼丹（含一键疗伤现炼）资源消耗降低 |
| 宗门 | `treasure`（新） | 寻宝 | 1000 | +10% → +25% | **任寻宝执事**时：全宗秘境探索最终收获提高，玄铁掉落概率同比例提高 |

与早先草案的两处差异：
- 「破障（突破成功率）」改为 **丹心**：突破成功率上限 95%，聚灵阵满级后已到顶，破障会没用；突破消耗也很小。聚气丹则是讨伐每关都发的。
- 「寻宝」不再加历练额外收获，只作用秘境（历练是单人行动，与执事「宗门加成」的定位不符）。

### 1.3 细则

- **新招弟子**：11 个天赋等概率随机（`names.ts` 的 `generateTalent`）。
- **战意**替代原「战斗天赋 ×1.15」：`discipleCombatPower` 里 `power × (1 + 战意bp/10000)`。金丹 = +15%，与现在持平；更高境界更强。
- **讨伐 Boss 血量估算不再计入天赋**（与装备一致）：`roundDamage` 估算处调用 `discipleCombatPower` 时不传天赋。
- **会心**：`rollDamage` 新增入参 `critBonusBase = Σ(会心弟子贡献 × 会心bp / 10000)`；暴击时伤害基数 = `partyBase × 1.5 + critBonusBase`，其余乘区不变。重伤（不计伤害）的成员不计入。
- **铁骨**：`rollOutcome` 新增入参 `injuryReductionBp`；重伤、受伤概率都 `× (1 − bp/10000)`（在体魄、狂暴修正之后）。
- **产出类**：`settle.ts` 的岗位产出倍率由固定 1.2 改为 `1 + talentBonusBp`；聚灵对应 `stoneMining` 与 `energyGathering` 两个岗位。
- **历练**：采集方向按天赋加成对应资源（灵植→药材、矿脉→矿石、聚灵→灵石），悟道加成历练修为；都改用随境界的值。
- **丹心**：聚气丹每颗修为 = `floor(120 × (1 + bp/10000))`；`cultivationPillsToFull` 按这个每颗增益算。弟子视图新增 `cultivationPillGain`（每人各自的值）。

## 2. 执事堂

### 2.1 规则

| 职位 id | 名称 | 需要的天赋 |
|---|---|---|
| `forging` | 炼器执事 | 炼器 |
| `alchemy` | 丹房执事 | 丹道 |
| `treasure` | 寻宝执事 | 寻宝 |

- 每个职位最多一人；只能任命拥有对应天赋的弟子。加成按**该执事当前境界**算（1.2 的表）。
- 执事是**职位，不是岗位**：岗位照常（可以继续修炼、突破、境界照常提升）。
- **执事不能出战**：讨伐、秘境（两种）、切磋挑战、进守擂阵容都拒绝。论道、服药、穿戴装备不受影响。
- **交接期**：卸任（含被新执事替换、洗髓换掉天赋）后 **12 小时**内不能出战。
- **每日一次**：同一职位每个 UTC+8 自然日只能任命一次（卸任不限）。
- 任命时拒绝：天赋不符、正在外历练、在守擂阵容里（提示先移出）。
- 执事在外历练期间加成**暂停**（人不在宗门）。
- 驱逐执事：职位清空，不产生交接期。

### 2.2 存储（迁移 `0034_talent_rework.sql`）

```sql
ALTER TABLE disciples ADD COLUMN talent_reroll_count INTEGER NOT NULL DEFAULT 0 CHECK (talent_reroll_count >= 0);
ALTER TABLE disciples ADD COLUMN talent_candidate TEXT;            -- 洗髓丹洗出、尚未决定的天赋 id；NULL = 无
ALTER TABLE disciples ADD COLUMN steward_handover_until INTEGER;   -- 交接期结束时间；NULL = 无

CREATE TABLE sect_stewards (
  sect_id TEXT NOT NULL REFERENCES sects (id),
  office TEXT NOT NULL,
  disciple_id TEXT,                 -- NULL = 空缺（保留行以记住当天已任命过）
  appointed_date_key TEXT NOT NULL DEFAULT '',
  updated_at INTEGER NOT NULL,
  PRIMARY KEY (sect_id, office)
);
```

- 快照 `SectSnapshot` 新增 `stewards: SectStewardRow[]`（`loadSnapshot` 多一条按主键前缀的小查询）。
- 驱逐弟子时同批把他所在职位的 `disciple_id` 置 NULL。

### 2.3 接口

- `POST /game/steward/appoint` `{ office, discipleId }`：校验 → upsert 职位行；原执事（如有）写交接期。
- `POST /game/steward/dismiss` `{ office }`：职位置空，原执事写交接期。
- 都返回 `{ state }`；`state.stewards` 给出三个职位的视图（当前执事、加成文案、是否暂停、今日能否任命）。

### 2.4 出战拦截

新增 `stewardBlocker(draft, disciple)`：是执事 →「任炼器执事，不能出战」；交接期内 →「刚卸任执事，交接中（还需 X 小时）」。
在 `exploreSectRealm`、`startRealmExplore`、`setDefenseLineup`、`challengeSect`、`attackWorldBoss` 的成员校验里调用（只拦这 5 个出战入口）。
弟子视图新增 `stewardOffice`（职位 id 或 null）、`combatBlockedReason`（执事 / 交接中的短原因，前端选人器据此禁选）。

## 3. 洗髓丹

- 丹药 id `talentPill`，名称「洗髓丹」，配方：药材 300、灵石 300、玄铁 5（展示单位）。走现有炼丹流程（受丹道折扣）。
- 功勋兑换：新分类「丹药」，洗髓丹 **60 功勋 / 颗**，可按个数兑换（与玄铁同一上限）。
- 服用（`POST /game/use-pill`，pillId = `talentPill`）：
  - 每人最多 **10 次**（`talent_reroll_count`）；有未决定的候选天赋时不能再服。
  - 从「除当前天赋外」的 10 个里等概率抽 1 个，写入 `talent_candidate`，次数 +1，库存 −1。
- 决定（`POST /game/talent-choice` `{ discipleId, accept }`）：
  - `accept = true`：`talent = candidate`；若他是执事且天赋变了 → 卸任（写交接期）。
  - `accept = false`：保留原天赋。两种都把 `talent_candidate` 置 NULL。
- 弟子视图新增 `talentRerollUses`、`talentRerollRemaining`、`talentCandidate`（`{ id, name, effect } | null`）。

## 4. 视图（`state`）新增

- `state.talents`：天赋总表 `{ id, name, category, categoryName, condition, values: { realmName, text }[] }[]`（弹窗表格用）。
- 弟子视图：`talentEffect`（当前境界下的效果，如「药园岗位产出 +25%」）+ 上面 2.4 / 3 的字段。
- `state.stewards`：三个职位视图 + `handoverHours`。
- 炼器面板（`buildEquipmentView`）的成功率计入炼器执事加成，并给出 `stewardBonusText`。
- 炼丹面板配方 `cost` 为丹道折后价；`alchemy.costDiscountText` 说明折扣来源。

## 5. 前端

1. **弟子详情**：天赋 tag 旁显示当前境界加成（`talentEffect`）；tag 旁一个「?」按钮，点开天赋总表弹窗（11 行 × 类别 / 生效条件 / 炼气→化神各档数值）。
2. **弟子详情 · 丹药**：服丹列表加洗髓丹（剩余次数、无候选才可服）；有候选天赋时显示「新天赋」卡片：原天赋 vs 新天赋，按钮「保留原天赋」「换成新天赋」。
3. **操作栏**新增「执事堂」：三个职位卡片（当前执事 / 境界 / 加成 / 暂停提示），任命（下拉选有对应天赋的弟子）、卸任；顶部写明规则。
4. **名册**：执事显示「执事」状态标，交接期显示「交接中」。
5. **选人器**（讨伐 / 秘境 / 切磋 / 守擂）：`combatBlockedReason` 非空则禁选并显示原因。论道不受影响。
6. **功勋兑换**：新增「丹药」页签，复用按个数兑换的面板。
7. **招贤**：候选人天赋名旁带上效果（title 提示）。
8. 更新说明一条。

## 8. 实施记录（开发中补充的决定）

- **铁骨**不减免「5 次起必重伤」那档（与体魄修正同一口径），只减免 30% / 70% 两档和普通受伤。
- **天机轮**奖池固定为原来三种丹药（`gambling.ts` 的 `WHEEL_PILL_IDS`）：否则转盘能低价拿到洗髓丹，且奖池一变所有宗门的格局都会变。
- **坊市**不回收洗髓丹（`shop.ts` 的 `SHOP_UNSELLABLE_PILL_IDS`）：否则功勋 → 洗髓丹 → 卖掉，等于功勋换灵石。
- **执事出战拦截**统一在 `service.ts` 的 `requireCanFight`；任命 / 卸任 / 二选一允许当事人在外历练或重伤（卸任不需要本人在场）。
- **招贤候选人**多带一个 `talentEffect`（炼气时的效果），候选卡片悬停可见。
- **首页操作栏**由 9 列改为 10 列（新增「执事堂」）；手机端 2 列正好 5 行。
- 测试：`tests/game/talent-rules.test.ts`（16 条规则）、`apps/server/test/talent.test.ts`（10 条接口）。
