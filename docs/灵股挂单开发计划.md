# 灵股挂单开发计划

灵股新增「挂单」：设好触发价和股数，价格到了自动成交，不用盯盘。三种挂单：限价买、限价卖、止损卖。

金额一律是**最小单位**（1 展示单位 = 1000 最小单位）；股价也是最小单位整数（`stockPriceAt` 的返回值）。
「今天」= UTC+8 自然日（`dateKeyUtc8` / `dayStartMs`）。

---

## 1. 产品规则（已和产品确认，不要改）

### 1.1 挂单类型

| kind | 名称 | 触发条件（某一分钟的价格 p） | 成交动作 |
|---|---|---|---|
| `limit_buy` | 限价买 | p ≤ 触发价 | 以 p 买入 N 股 |
| `limit_sell` | 限价卖 | p ≥ 触发价 | 以 p 卖出 N 股 |
| `stop_sell` | 止损卖 | p ≤ 触发价 | 以 p 卖出 N 股 |

- 成交价 = **第一次满足条件那一分钟**的价格（`stockPriceAt(seed, stock, minute)`），成交时间 = 那一分钟的起点（`minute × 60000`）。
- 从下单那一分钟（`marketMinuteOf(created_at)`）开始算，下单时价格已经满足条件就在当前这一分钟成交。

### 1.2 冻结

- **限价买**：下单时冻结 `触发价 × 股数 + marketFee(触发价 × 股数)` 灵石（从余额扣掉，记在挂单的 `reserved`）。成交时实付 `成交价 × 股数 + 手续费`，差额退回；撤单 / 到期 / 成交失败时 `reserved` 全额退回。
- **限价卖 / 止损卖**：下单时**锁定**股数，不从持仓里扣。可用股数 = 持有股数 − 本宗所有未完成卖单（两种卖单都算）的股数之和。下卖单和手动卖出都只能用「可用股数」。

### 1.3 现有规则照样生效（成交时检查）

- **手续费** 0.3%（`marketFee`）。
- **每日 30 笔**（`MARKET_DAILY_TRADES`）：挂单成交也写一行 `stock_trades`、也算一笔。某一分钟所在的那一天已满 30 笔，这一分钟不能成交，继续往后找（到第二天自然有额度）。
- **买入后 10 分钟内不能卖**：卖单只在 `minute × 60000 ≥ marketSellableAt(last_buy_at)` 的分钟才能成交。
- **持仓上限**（`marketPositionCap`）：下限价买单时检查一次（按触发价）；成交时再检查一次（按成交价），超了就**取消这一单**并全额退回冻结灵石。
- 卖单成交时持有股数不够（理论上不会，锁定过），同样取消这一单。

### 1.4 限制

- 每个宗门同时最多 **5** 个未完成挂单（`MARKET_ORDER_MAX_OPEN = 5`）。
- 有效期 **72 小时**（`MARKET_ORDER_TTL_MS = 72 × 3600000`）：过了还没成交，状态改为「已过期」，买单退回冻结灵石。
- 一单 1～`MARKET_MAX_SHARES_PER_TRADE` 股；触发价为正整数（最小单位）。
- 可随时撤单（只能撤本宗、状态为 open 的单）。

### 1.5 通知

- 成交、到期、因持仓上限等原因被取消时，往本宗**天机录**写一条（用现有的 `insertEventLogStatement`，看现有调用怎么填字段）。
  - 例：「限价买入天工坊 100 股成交，成交价 47.312」「止损卖出聚灵阁 50 股成交……」「天工坊限价买单已过期，退回 4750 灵石」。

## 2. 代码结构

### 2.1 规则（`apps/server/src/modules/game/market.ts`，追加，纯函数）

- 常量：`MARKET_ORDER_KINDS = ['limit_buy', 'limit_sell', 'stop_sell'] as const`、`MARKET_ORDER_MAX_OPEN = 5`、`MARKET_ORDER_TTL_MS`。
- `orderTriggered(kind, price, triggerPrice): boolean`。
- `limitBuyReserve(triggerPrice, shares)`：冻结额。
- `findOrderFill(input)`：纯函数，给定 `seed`、`stock`、`kind`、`triggerPrice`、`fromMinute`、`toMinute`（含）、`sellableAt`（卖单用，可为 null）、以及 `tradesUsedOnDay(dateKey) => number`（回调，返回那一天已成交笔数）和 `MARKET_DAILY_TRADES`，逐分钟找第一个满足「触发 + 可卖时间 + 当天没满 30 笔」的分钟，返回 `{ minute, price } | null`。

### 2.2 迁移 `migrations/0049_stock_orders.sql`（文件头格式照 0044）

```
stock_orders(
  id TEXT PRIMARY KEY,
  sect_id TEXT NOT NULL,
  stock_id TEXT NOT NULL,
  kind TEXT NOT NULL CHECK (kind IN ('limit_buy', 'limit_sell', 'stop_sell')),
  shares INTEGER NOT NULL CHECK (shares > 0),
  trigger_price INTEGER NOT NULL CHECK (trigger_price > 0),
  reserved INTEGER NOT NULL DEFAULT 0 CHECK (reserved >= 0),
  status TEXT NOT NULL DEFAULT 'open' CHECK (status IN ('open', 'filled', 'cancelled', 'expired')),
  -- 已经检查到哪一分钟（含）：每次只扫新的分钟，避免 72 小时 × 每次全扫
  checked_minute INTEGER NOT NULL,
  fill_price INTEGER,
  filled_at INTEGER,
  close_reason TEXT,          -- 'filled' / 'user' / 'expired' / 'position_cap' / 'no_shares'
  version INTEGER NOT NULL DEFAULT 0 CHECK (version >= 0),
  created_at INTEGER NOT NULL,
  expires_at INTEGER NOT NULL,
  updated_at INTEGER NOT NULL
)
索引：(sect_id, status)、(status, checked_minute)
```

下单时 `checked_minute = marketMinuteOf(created_at) − 1`（还没检查过任何一分钟）。

### 2.3 Repository（`repository.ts`，照 `MarketRepository` / 拍卖的写法）

- 读：本宗未完成单、本宗最近 10 条已结束单、全服待检查的 open 单（`ORDER BY checked_minute LIMIT ?`）、本宗某股未完成卖单股数之和、某一天（dayStart 起到下一天 dayStart 前）本宗成交笔数。
- 写：插入挂单、更新挂单（状态 / 成交价 / checked_minute / version+1）、挂单 version 守卫（照 `sectTowerGuardStatement` / `auctionLotGuard`）。
- 持仓写回与守卫沿用现有的 `upsertStockHoldingStatement`、`stockHoldingGuardStatement`；成交流水沿用 `insertStockTradeStatement`（`now` 传成交时间）；退款 / 卖出所得用 `resourceDeltaStatement`（与拍卖结算同一做法，不夹容量）。

### 2.4 Service（`service.ts`，放在灵股那一节）

1. `placeStockOrder(db, userId, input: { stockId, kind, shares, triggerPrice }, now)`：
   - 先 `processSectStockOrders(db, sectId, now)`（见 3），再 `draftFor`；`requireMarketUnlocked`；校验股票、股数、触发价、未完成单数 < 5。
   - 限价买：按触发价检查持仓上限；`draft.requireResource('spiritStone', reserve)`。
   - 卖单：股数 ≤ 可用股数。
   - 插入挂单，`draft.commit()`（卖单要带持仓 version 守卫，防止并发卖光）。
   - 返回 `{ state, market }`。
2. `cancelStockOrder(db, userId, orderId, now)`：只能撤本宗 open 单；状态改 cancelled（close_reason `user`）；买单 `draft.grantResource('spiritStone', reserved)`；带挂单 version 守卫提交。返回 `{ state, market }`。
3. `processSectStockOrders(db, sectId, now)` 与 `processStockOrders(db, now)`（定时任务用，单次最多处理 200 单，每单各自 try/catch，照 `processAuctions`）：
   - 对每个 open 单：`from = checked_minute + 1`，`to = min(marketMinuteOf(now), marketMinuteOf(expires_at))`；`findOrderFill` 找成交分钟。
   - 找到 → 按 1.3 再检查持仓上限 / 持有股数，通过则成交：写持仓、成交流水（`created_at = 成交时间`）、退款或卖出所得、挂单状态 filled + fill_price + filled_at、天机录；不通过则取消并退款、写天机录。
   - 没找到且 `now ≥ expires_at` → expired，买单退款，写天机录。
   - 否则只把 `checked_minute` 推进到 `to`。
   - 每单一个 batch：挂单 version 守卫 + 持仓 version 守卫（成交时）；守卫失败就跳过（下次再来），用 `isGuardFailure` 判断，照 `settleAuctionLot`。
4. `getMarket` 与 `tradeStock` 开头先调 `processSectStockOrders`；`tradeStock` 的手动卖出改为只允许卖「可用股数」（超出时提示「有 N 股挂着卖单，可卖 M 股」）。
5. `apps/server/src/scheduled.ts`：加一段 `processStockOrders`（单独 try/catch，照现有几段）。

## 3. 测试

### 3.1 规则 `tests/game/market-orders-rules.test.ts`

- `orderTriggered` 三种类型的边界（等于触发价也成交）。
- `limitBuyReserve` = 金额 + 手续费。
- `findOrderFill`：返回第一个满足的分钟；可卖时间之前的分钟跳过；某天已满 30 笔时跳到下一天；区间内都不满足返回 null（用固定 seed，先算出一段价格再挑触发价）。

### 3.2 接口 `apps/server/test/market-orders.test.ts`（工具照 `apps/server/test/market.test.ts`）

- 下限价买单：冻结正确；第 6 单被拒；触发价按当前价设成必成交 → 处理后成交，持仓与成交流水正确，差额退回。
- 下卖单：超过可用股数被拒；锁定后手动卖出只能卖可用部分。
- 止损卖：价格 ≤ 触发价时成交；买入 10 分钟内不成交，过了才成交。
- 撤单：退回冻结；不能撤别人的单、不能撤已结束的单。
- 到期：72 小时没成交 → expired，买单退款，天机录有一条。
- 每日 30 笔：当天已满 30 笔时不成交，第二天成交。
- 并发：同一单被两次处理只成交一次。
