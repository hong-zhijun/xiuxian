# 弱模型执行提示词：赌坊系统（论道赌局）

请在当前项目目录中直接实现 `docs/赌坊开发计划.md` 规定的赌坊系统。先完整阅读该文档和当前相关源码，再修改代码；不要只给方案，不要停在分析阶段。

## 执行要求

1. 以 `docs/赌坊开发计划.md` 为唯一需求来源。
2. 先检查当前工作树，保留已有用户改动，不要重置或覆盖无关文件。
3. 严格按照文档第 12 节的实施顺序开发：迁移与仓储 → 纯函数 → View 类型与 sync → Service → Schema 与 Routes → 前端 API → 前端组件 → 类型检查。
4. 赌坊由"宗门 2 级"解锁，不依赖建筑。
5. 不修改 `GameConfigContent`、`GAME_CONFIG_VERSION`、`GAME_CONFIG_PAYLOAD_HASH` 和 `/config/public` 契约。
6. 第一版只实现三种赌注模式：系统预设灵石、自由输入资源、属性赌注。
7. 所有写操作必须沿用现有 `SectDraft`，先结算，再校验，再通过一次 D1 batch 写入；复用已有 `mutation_guards` 快照守卫模式。
8. 所有金额使用现有最小单位整数（1 展示单位 = 1000 最小单位）；前端 `formatAmount` 已做除法。
9. jev Decisions API 集成参照 `service.ts` 中 `judgeExploreChoice` 的模式：`readStringVar(env.OPENROUTER_API_KEY)` 读 key、`decide()` 调用、失败降级到本地固定概率。
10. 悟道值加点在弟子详情面板（`DiscipleDetailDialog.vue`）中操作，emit 事件给上层组件处理。
11. 赌坊面板在 `SectScreen.vue` 中作为新的 `openPanel` 值集成，使用 `ModalShell` 包裹。
12. 不引入 Vue Router、Pinia、异步队列、定时任务、玩家对战赌局或新的货币类型。
13. 前端组件使用 Vue 3 `<script setup>` + Composition API，与项目现有风格保持一致。
