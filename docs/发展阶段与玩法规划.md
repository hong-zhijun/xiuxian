# 《开山立派》发展阶段与玩法规划

> 基于 2026-11-03 对全仓（80 个 migration、server 模块、前端入口、更新日志）的盘点。
> 结论先行：**现在的问题不是玩法不够多，是玩法太多但没有一个能把人留住。**

---

## 一、现状诊断

### 1.1 迭代节奏

仓库 10/16 建起，到 11/03 共 80 个数据库迁移——平均每天上线 2~3 个玩法。同期核心循环
（挂机产资源 → 弟子上境界 → 宗门升级）**从未改变过一次**。所有产能都投向了横向扩展。

### 1.2 三个危险信号

**① 硬顶已经顶到**

| 维度 | 上限 | 位置 |
|---|---|---|
| 宗门等级 | 15 | `constants.ts:460` |
| 弟子境界 | 渡劫后期（9 境界 × 3 阶段） | `constants.ts:112` |
| 飞升 | 1 级 | `0077_ascension.sql` CHECK `ascension_level <= 1` |

老玩家打完即纯空转，没有任何后续内容承接。

**② 靠发钱续命**

18 天内 5 次全服贺礼：10/23 周五福利、10/24 刮刮乐上线、10/30 一键祭炼、10/31 飞升、
11/01 全民修炼补给。全部是 migration 里一把 `UPDATE resource_balances`，不可配置、不可复用、
无领取流程。这是内容供给跟不上消耗速度的典型症状。

**③ 数值在失控**

| 日期 | 改动 | 后果 |
|---|---|---|
| 10/26 | 取消仓库上限（`RESOURCE_CAPACITY = MAX_SAFE_INTEGER`） | 资源可无限囤积 |
| 10/30 | 修炼速度 60 → 600 | 境界成长 ×10 |
| 10/31 | 灵气产速 20 → 200、吐纳 10 → 100 | 破境成本贬值 ×10 |

每拆一道闸门，坊市、赌坊、灵股作为「资源出口」的意义就少一分。现在 `SECT_LEVELS.capacityMultiplier`
（1→64）只剩坊市持仓上限一个用途。

### 1.3 产能过剩：横向堆叠，互抢入口

- **PVE 出口 6 个**：速通秘境、交互式秘境、弟子历练、镇妖塔、世界 BOSS、灵兽捕捉——
  抢的是同一批弟子和同一份在线时间。
- **博弈 5 个**：论道、天机轮、灵兽竞逐、赌石、刮刮乐——共享每日 50 次，互相挤占。
- **市场 4 个**：坊市、灵股（含挂单/保证金）、拍卖行、云游商人——在仓库无上限后集体失重。

### 1.4 地基空白：代码里完全没有

- 无签到 / 连续登录
- 无成就系统
- 无新手引导 / 主线任务链（只有每日随机 5 个的「日课」）
- 无好友 / 私聊 / 邮件 / 联盟
- 无赛季 / 转生 / 新周目

### 1.5 死产出（有产出、无出口）

| 资源 | 产出 | 现有出口 |
|---|---|---|
| 声望 `sects.reputation` | 仅宗门挑战（+5~+20，每日 3 次） | **仅排行榜排序** |
| 御兽精魄 `beastEssence` | 仅放生灵兽 | 兑换 1 级凡品灵兽、品质突破 |
| 功勋 `bossMerit` | 仅世界 BOSS | 固定商店 4 类，无随机 |
| 灵兽图鉴 `beast_collection` | 自动统计 | **纯展示，零奖励** |

### 1.6 死代码

- `sparring_log`（0007 切磋）：表与 service 都在，`routes.ts` 无路由，
  `dailyTasks.ts:56` 注释明确「切磋没有开放入口，做不了」。
- `spirit_veins` / `vein_battles` / `sect_vein_stats`（0042 灵脉）：全仓零引用，
  已被 0051 山河舆图取代。
- `sects.vein_level`：遗留字段，无任何读写。
- `recruitment.dailyLimit`（=3）：0021 起已废弃，配置里留着会误导。

## 二、三个转向

1. **从「横向加玩法」到「纵向加深度」。** 把 6 个 PVE 串成有层级的挑战链，
   而不是加第 7 个。
2. **从「资源通胀」到「稀缺与选择」。** 把死产出接上出口，比发 5 万灵石有效得多。
3. **从「单机挂机」到「真社交」。** 现在所有多人玩法都是异步快照，玩家间零对话零协作。

---

## 三、路线图总览

| 阶段 | 周期 | 目标 | 内容 |
|---|---|---|---|
| 一、止血 | 1~2 周 | 搭留存骨架 | 签到与成就、声望出口、新手引导 |
| 二、做深 | 3~5 周 | 破硬顶、建黏性 | 转生新周目、师徒与羁绊、仙盟 |
| 三、盘活 | 持续 | 让存量联动 | 灵兽接秘境、建筑补种、清理死表 |

## 四、阶段一：止血（1~2 周）

这一阶段几乎不新增玩法，但能把留存骨架搭起来。

### 4.1 签到与连续登录

**目标**：把「全服发钱」这种不可持续的福利，换成可配置、有节奏的日常发放。

7 天循环奖励（展示单位）：

| 天 | 奖励 |
|---|---|
| 1 | 灵石 5,000 |
| 2 | 药材 2,000 |
| 3 | 矿石 2,000 |
| 4 | 灵气 5,000 |
| 5 | 随机丹药 ×1 |
| 6 | 玄铁 ×2 |
| 7 | 神木 ×1 + 灵石 20,000 |

- 断签清零；每月可补签 3 次（每次消耗 500 灵石）。
- 连续 30 天额外大奖：天阶功法残卷 ×5。

```sql
-- Migration: 0081_checkin
CREATE TABLE sect_checkin (
  sect_id TEXT NOT NULL PRIMARY KEY,
  streak INTEGER NOT NULL DEFAULT 0,          -- 连续天数，断签清零
  month_key TEXT NOT NULL,                    -- YYYY-MM，用于补签计数
  total_days INTEGER NOT NULL DEFAULT 0,
  last_checkin_date TEXT,
  makeup_used INTEGER NOT NULL DEFAULT 0 CHECK (makeup_used BETWEEN 0 AND 3),
  created_at INTEGER NOT NULL,
  updated_at INTEGER NOT NULL
);
```

### 4.2 成就系统（本阶段性价比最高的一件）

**目标**：一次性盘活「声望 / 精魄 / 图鉴」三个死产出。

已有大量「只统计不回馈」的数据可复用：镇妖塔层数、灵兽图鉴 `seen_count/caught_count`、
大比名次、秘境通关数、赌坊累计次数、世界 BOSS 累计伤害。

| 分类 | 成就示例 |
|---|---|
| 宗门 | 宗门 5 / 10 / 15 级、弟子 20 / 40 / 64 人 |
| 修为 | 首个金丹 / 元婴 / 化神 / 渡劫、飞升 1 名 |
| 战斗 | 镇妖塔 50 / 100 / 200 层、BOSS 累计伤害 100 万、大比夺冠 |
| 收集 | 灵兽图鉴 20 / 40 / 60 种、仙品灵兽、功法收录 6 / 12 门 |
| 经济 | 拍卖成交 10 次、赌石开出天外陨石、灵股累计盈利 10 万 |
| 山河 | 占据祖脉、累计供奉 1 万灵气 |

奖励档位：

| 档 | 奖励 |
|---|---|
| 铜 | 声望 50 + 灵石 20,000 |
| 银 | 声望 150 + 御兽精魄 50 |
| 金 | 声望 500 + 专属头像框 |

```sql
-- Migration: 0082_achievements
CREATE TABLE sect_achievements (
  sect_id TEXT NOT NULL,
  achievement_id TEXT NOT NULL,
  progress INTEGER NOT NULL DEFAULT 0,
  claimed INTEGER NOT NULL DEFAULT 0 CHECK (claimed IN (0, 1)),
  claimed_at INTEGER,
  updated_at INTEGER NOT NULL,
  PRIMARY KEY (sect_id, achievement_id)
);
```

> 实现要点：进度统一走「读取时从现有记录表现算」，与 0048 日课的做法一致，
> 不额外埋点、不写双份。

### 4.3 声望出口

**现状**：声望唯一产出是宗门挑战（每日 3 次 × 最多 20 = 60/天，月约 1,800），
唯一用途是排行榜排序。挑战玩法因此几乎是死的——赢了没感知。

声望商店（新增 `reputation` 作为可消费资源）：

| 商品 | 声望 |
|---|---|
| 御兽精魄 ×10 | 100 |
| 洗髓丹 / 培元丹 ×1 | 200 |
| 头像框（3 款轮换） | 300 ~ 800 |
| 称号「后起之秀」（全资源产出 +2%，永久） | 500 |
| **天阶功法残卷 ×1** | 800 |
| 宗门改名令 | 1,000 |

> 第 5 项顺带解决「天阶残卷断供」：`TECHNIQUE_SHOP_TIERS` 目前只有 `xuan/di`，
> 天阶只能靠世界 BOSS 第 6 关起掉落或游商 10% 概率，非 BOSS 玩家几乎拿不到。

### 4.4 新手引导与主线任务链

**现状**：20+ 个玩法入口，零引导，新玩家必懵。

四章主线，每章 4~5 步，串起现有玩法：

| 章 | 名称 | 步骤（示例） | 奖励递增 |
|---|---|---|---|
| 一 | 开山 | 建宗 → 招 3 弟子 → 派工 → 首次破境 → 宗门 2 级 | 灵石 1 万 |
| 二 | 立派 | 炼丹 ×1 → 炼器 ×1 → 镇妖塔 10 层 → 宗门 3 级 | 玄铁 5 |
| 三 | 扬名 | 秘境 ×3 → 挑战 ×1 → BOSS 出手 ×1 → 宗门 5 级 | 神木 3 |
| 四 | 问鼎 | 拍卖 ×1 → 灵股 ×1 → 山河占 1 处 → 宗门 8 级 | **仙品装备箱** |

## 五、阶段二：做深（3~5 周）

### 5.1 转生 · 开辟新界

**唯一能真正解决硬顶的方案。** 比再加一个境界稳得多——挂机游戏的长线基本都靠这个。

**触发条件**：宗门 15 级 且 至少 1 名弟子已成仙。

**效果**

- 保留：建筑等级、功法等级、装备、灵兽、成就、声望、头像框、灵兽苑
- 重置：宗门等级归 1；弟子散功为炼气初期（保留姓名 / 天赋 / 洗髓淬体次数）；资源保留 30%
- 永久加成（可叠加）：全资源产出 +10%、突破成功率 +5%、全弟子战力 +5%
- 新增货币「道韵」，只由转生产生，兑换专属外观与永久加成

```sql
-- Migration: 0084_rebirth
CREATE TABLE sect_rebirth (
  sect_id TEXT NOT NULL PRIMARY KEY,
  cycle INTEGER NOT NULL DEFAULT 0,        -- 当前周目
  dao_yun INTEGER NOT NULL DEFAULT 0,      -- 道韵
  bonus_production_bp INTEGER NOT NULL DEFAULT 0,
  bonus_breakthrough_bp INTEGER NOT NULL DEFAULT 0,
  bonus_power_bp INTEGER NOT NULL DEFAULT 0,
  last_rebirth_at INTEGER,
  created_at INTEGER NOT NULL,
  updated_at INTEGER NOT NULL
);
```

### 5.2 师徒与羁绊

**目标**：让 64 个弟子从「数字」变成「角色」。这是目前最大的浪费——
弟子只影响产出数值，彼此之间没有任何关系。

- **师徒**：师傅需元婴及以上，徒弟低于师傅 2 个大境界。拜师后徒弟修为 +15%，
  师傅积累传道值；徒弟出师（达到师傅境界）后师傅获得永久属性加成。
  同时最多 3 对（随宗门等级提升）。
- **羁绊**：弟子间存在「同门 / 道侣 / 宿敌」关系（招募时随机生成，可用洗髓丹洗），
  同时出战触发加成（例：道侣同在镇妖塔队伍 → 战力 +8%）。

```sql
-- Migration: 0085_disciple_relations
CREATE TABLE disciple_relations (
  id TEXT NOT NULL PRIMARY KEY,
  sect_id TEXT NOT NULL,
  mentor_id TEXT NOT NULL,
  disciple_id TEXT NOT NULL,
  kind TEXT NOT NULL,              -- mentorship | bond
  bond_kind TEXT,                  -- 同门 | 道侣 | 宿敌
  teaching_value INTEGER NOT NULL DEFAULT 0,
  started_at INTEGER NOT NULL,
  graduated_at INTEGER,
  mentor_bonus TEXT NOT NULL DEFAULT '[]'   -- JSON：出师后师傅的永久加成
);
CREATE INDEX idx_disciple_relations_sect ON disciple_relations(sect_id, kind);
```

### 5.3 仙盟

**目标**：一次解决声望出口、社交黏性、全服 BOSS 三件事。

- 消耗声望 1,000 创建「结盟帖」，3~5 个宗门结盟。
- **联盟频道**：`chat_messages` 加 `channel` 字段（默认 `'world'`）即可承载，
  改动极小。
- **联盟 BOSS**：每周一个，成员共同讨伐，按伤害排行发「盟贡」。
- **盟贡商店**：天阶残卷、仙品材料、专属头像框。


## 七、明确不建议的方向

1. **第 7 个 PVE 或第 6 个博弈玩法。** 边际收益已是负的——每加一个都在稀释
   已有玩法的活跃度，并进一步加重新手的认知负担。
2. **实时对战。** Workers 是请求-响应 + Cron 架构，聊天现在还是轮询，
   做实时同步的成本与收益不成比例。所有 PvP 保持异步快照是正确的技术选择。
3. **继续用「全服发钱」式福利。** 会加速通胀，且不可配置、不可复用。
   阶段一 4.1 / 4.2 完成后应完全停掉。

## 八、顺带要修的技术债

| 项 | 问题 |
|---|---|
| Cron 频率不一致 | `apps/server/wrangler.jsonc` 是 `* * * * *`，根 `wrangler.jsonc` 是 `*/10 * * * *`。灵兽竞逐 10 分钟一轮（投注期 8 分钟）在 10 分钟调度下会明显延迟 |
| `WORLD_BOSS_DAILY_ATTACK_LIMIT` | 只在根 `wrangler.jsonc` 声明（=120），`apps/server` 那份没有；changelog 说已取消上限，vars 与实现不同步 |
| `REALM_EXPLORE_ENABLED` | 交互式探索有开关，赌石等没有对应开关，粒度不一致 |
