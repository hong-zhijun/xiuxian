# 宗门大比开发计划

## 1. 概述

宗门大比是一个**每日自动结算**的竞技系统，分为**个人赛（斗法）**和**团队赛（宗门战）**两部分。每天中午 12:00（UTC+8）自动结算所有比赛，出战报和排名。每周为一个赛季，周日中午结算赛季排名并发放赛季大奖。

### 核心设计原则

- **零操作门槛**：不报名的宗门也自动参与（取最强弟子），报名只是为了手动优化阵容。
- **公平性**：个人赛用 handicap（弱方属性补偿）；团队赛限制总战力上限。
- **轻量感**：每天只出结果，不需要玩家在线操盯。
- **修仙文案**：斗法台、宗门战、赛季称号等贴近修仙主题。

### 时间线

| 阶段 | 时间（UTC+8） |
|---|---|
| 报名/调阵容 | 每天 0:00 ~ 12:00 |
| 结算 | 每天 12:00 |
| 赛季结算 | 每周日 12:00（结算完当天比赛后紧跟着结算赛季） |

## 2. 个人赛（斗法台）

### 2.1 报名与参赛

- 每个宗门最多报名 **5 名弟子**参加斗法台。
- 可在 0:00~12:00 之间设置/修改出战弟子名单。
- **未报名的宗门自动参赛**：系统自动取战力最强的 5 名可出战弟子（排除执事、坐镇、重伤卧床弟子）。
- 前端需要明确标注「已报名」和「未报名（自动取最强弟子参赛）」两种状态。

### 2.2 对战规则

- **全员循环赛**：所有参赛弟子两两配对，每对打一场 1v1。
- **双向回合制**：复用镇妖塔的战斗框架，改为弟子 A vs 弟子 B 互相打。

#### 战斗模拟（simulateArenaDuel）

- 双方各有血量：`HP = 4.5 × 战力 × (0.5 + 体魄 / 100) × DAMAGE_SCALE`（沿用镇妖塔公式）。
- 最多 **10 回合**。
- 每回合：身法高的先出手。
  - 出手伤害 = `战力 × 攻击修正 × handicap系数 × 浮动(0.8~1.2) × 暴击`。
  - 暴击率 = `幸运 / 100 × 20%`，暴击伤害 ×1.5。
  - 追击：身法每比对方高 1 点 +0.5%，最高 30%。
  - 防御减免：`100 / (100 + 对方防御)`。
- 10 回合结束未分胜负：按**剩余血量百分比**高的一方获胜；相同则平局（双方各得 0.5 个胜场）。

#### Handicap（补偿机制）

- 每场对战根据双方战力差对弱方做属性加成：
  - `补偿系数 = min(0.5, (对方战力 / 我方战力 - 1) × 0.5)`
  - 弱方的 attack / defense / speed / luck / physique 全部 × `(1 + 补偿系数)`。
- 战力高的一方无补偿。
- 效果：战力 300 vs 战力 600 时，弱方属性 +50%，有翻盘机会但不保证。

### 2.3 积分与排名

- 胜一场得 **3 分**，平局 **1 分**，负 **0 分**。
- 每天出日榜（按当日积分排序）。
- 赛季分 = 7 天的日积分累计。

### 2.4 每日奖励

所有参赛弟子的奖励发放到**弟子所属宗门**（灵石入宗门资源，丹药入宗门背包）。

| 日排名 | 灵石（展示单位） | 修为丹 |
|---|---|---|
| 第 1 名 | 1000 | 5 |
| 第 2~3 名 | 600 | — |
| 参与奖（其余） | 300 | — |

### 2.5 赛季奖励（周日结算）

| 赛季排名 | 灵石（展示单位） | 修为丹 |
|---|---|---|
| 总冠军 | 500 | 3 |
| 第 2~3 名 | 300 | 1 |

## 3. 团队赛（宗门战）

### 3.1 报名与参赛

- 每个宗门出 **5 名弟子**组成战队。
- 可在 0:00~12:00 之间设置/修改出战名单与出战顺序。
- **未报名的宗门自动参赛**：系统自动取战力最强的 5 名可出战弟子。
- **总战力上限**：出战 5 人的总战力不能超过上限值。超过上限的宗门需要自己调换弟子。
  - 上限 = 所有宗门等级 ≥ 2 的宗门的「前 5 弟子总战力」的**平均值**。
  - 每周一 0:00 刷新上限值（赛季内不变）。
  - 自动参赛的宗门如果总战力超限，从最强往最弱逐个替换为下一个可出战弟子，直到不超限为止。

### 3.2 对战规则

- **循环赛**：每两个宗门打一场。
- **车轮战**：双方各 5 人按排位依次 1v1。
  - 赢方弟子留在场上（血量不回复，保留当前剩余血量）继续打对方下一人。
  - 输方换下一人上场（满血）。
  - 一方 5 人全部倒下则该宗门负。
- 车轮战的每场 1v1 使用与个人赛相同的战斗模拟（simulateArenaDuel），但有额外的**团队赛 handicap**。

#### 团队赛 Handicap

- 比较双方宗门出战总战力（不是个人战力），对总战力低的宗门的**每个弟子**做属性加成：
  - `补偿系数 = min(0.5, (对方宗门总战力 / 我方宗门总战力 - 1) × 0.5)`
- 这个补偿叠加在个人战力 handicap 之上（两层 handicap 取较大值，不叠乘）。

### 3.3 积分与排名

- 宗门胜一场得 **3 分**，负 **0 分**（车轮战没有平局）。
- 每天出日榜（按当日积分排序，同分看总击杀数）。
- 赛季分 = 7 天的日积分累计。

### 3.4 每日奖励

| 日排名 | 灵石（展示单位） | 矿石（展示单位） | 功勋（展示单位） |
|---|---|---|---|
| 第 1 名 | 1500 | 750 | 25 |
| 第 2~3 名 | 900 | 400 | 15 |
| 参与奖（其余） | 400 | 200 | 5 |

### 3.5 赛季奖励（周日结算）

| 赛季排名 | 灵石（展示单位） | 功勋（展示单位） | 额外 |
|---|---|---|---|
| 第 1 名 | 1000 | 15 | 玄铁 ×3 |
| 第 2~3 名 | 500 | 8 | 玄铁 ×1 |

## 4. 赛季机制

- **周一到周六**：每天 12:00 比赛，积分累计。
- **周日 12:00**：最后一场比赛 + 结算赛季总排名 + 发奖 + 清空积分。
- **下周一 12:00**：新赛季第一场。新赛季的团队赛战力上限在周一 0:00 重新计算。

## 5. 战报与赛程图

### 5.1 赛程图

- 首页「宗门大比」面板展示**赛程图**，层级结构：

  - 个人赛赛程图：按日显示全部 1v1 对阵结果，分轮展示（类似淘汰赛图但实际是循环赛，用表格/卡片列出每轮对阵）。
  - 团队赛赛程图：按日显示每两个宗门的车轮战结果，展开可看每场 1v1 详情。
- 每场对战卡片显示：双方名字、战力、胜负、关键数据（总伤害 / 击杀数）。
- 点击展开可看回合详情。

### 5.2 报名状态面板

- 进入宗门大比页面，顶部显示：
  - **已报名**的宗门：列出宗门名 + 出战弟子名单。

## 6. 数据库设计

### 新建迁移：0053_arena_tournament.sql

```sql
-- 宗门大比赛季
CREATE TABLE arena_seasons (
  id TEXT PRIMARY KEY,                    -- 赛季 id（如 '2026-W42'）
  start_date TEXT NOT NULL,               -- 赛季起始日期（UTC+8，如 '2026-10-13'）
  end_date TEXT NOT NULL,                 -- 赛季结束日期
  team_power_cap INTEGER,                 -- 团队赛战力上限
  settled INTEGER NOT NULL DEFAULT 0,     -- 是否已结算赛季奖励（0/1）
  created_at INTEGER NOT NULL
);

-- 宗门大比报名（个人赛 + 团队赛共用）
CREATE TABLE arena_entries (
  sect_id TEXT NOT NULL,
  kind TEXT NOT NULL CHECK (kind IN ('individual', 'team')),
  -- 出战弟子 id 的 JSON 数组（按出战顺序）；自动参赛的也写入（标记 auto = 1）
  lineup TEXT NOT NULL,
  auto INTEGER NOT NULL DEFAULT 0,        -- 0 = 手动报名, 1 = 系统自动
  date_key TEXT NOT NULL,                 -- UTC+8 日期（如 '2026-10-13'）
  created_at INTEGER NOT NULL,
  PRIMARY KEY (sect_id, kind, date_key)
);

-- 个人赛每日积分
CREATE TABLE arena_individual_scores (
  date_key TEXT NOT NULL,
  disciple_id TEXT NOT NULL,
  sect_id TEXT NOT NULL,
  disciple_name TEXT NOT NULL,
  combat_power INTEGER NOT NULL,
  wins REAL NOT NULL DEFAULT 0,           -- 胜场（平局算 0.5）
  losses REAL NOT NULL DEFAULT 0,
  points INTEGER NOT NULL DEFAULT 0,      -- 积分
  total_damage INTEGER NOT NULL DEFAULT 0,
  created_at INTEGER NOT NULL,
  PRIMARY KEY (date_key, disciple_id)
);

CREATE INDEX idx_arena_ind_scores_date ON arena_individual_scores (date_key, points DESC);

-- 团队赛每日积分
CREATE TABLE arena_team_scores (
  date_key TEXT NOT NULL,
  sect_id TEXT NOT NULL,
  sect_name TEXT NOT NULL,
  team_power INTEGER NOT NULL,
  wins INTEGER NOT NULL DEFAULT 0,
  losses INTEGER NOT NULL DEFAULT 0,
  points INTEGER NOT NULL DEFAULT 0,
  kills INTEGER NOT NULL DEFAULT 0,       -- 总击杀数（同分排序用）
  created_at INTEGER NOT NULL,
  PRIMARY KEY (date_key, sect_id)
);

CREATE INDEX idx_arena_team_scores_date ON arena_team_scores (date_key, points DESC);

-- 赛季累计积分（个人）
CREATE TABLE arena_season_individual (
  season_id TEXT NOT NULL,
  disciple_id TEXT NOT NULL,
  sect_id TEXT NOT NULL,
  disciple_name TEXT NOT NULL,
  total_points INTEGER NOT NULL DEFAULT 0,
  total_wins REAL NOT NULL DEFAULT 0,
  total_losses REAL NOT NULL DEFAULT 0,
  created_at INTEGER NOT NULL,
  PRIMARY KEY (season_id, disciple_id)
);

-- 赛季累计积分（团队）
CREATE TABLE arena_season_team (
  season_id TEXT NOT NULL,
  sect_id TEXT NOT NULL,
  sect_name TEXT NOT NULL,
  total_points INTEGER NOT NULL DEFAULT 0,
  total_wins INTEGER NOT NULL DEFAULT 0,
  total_losses INTEGER NOT NULL DEFAULT 0,
  total_kills INTEGER NOT NULL DEFAULT 0,
  created_at INTEGER NOT NULL,
  PRIMARY KEY (season_id, sect_id)
);

-- 对战记录（个人赛每场 1v1）
CREATE TABLE arena_individual_matches (
  id TEXT PRIMARY KEY,
  date_key TEXT NOT NULL,
  -- 甲方
  fighter_a_id TEXT NOT NULL,
  fighter_a_name TEXT NOT NULL,
  fighter_a_sect_id TEXT NOT NULL,
  fighter_a_power INTEGER NOT NULL,
  -- 乙方
  fighter_b_id TEXT NOT NULL,
  fighter_b_name TEXT NOT NULL,
  fighter_b_sect_id TEXT NOT NULL,
  fighter_b_power INTEGER NOT NULL,
  -- 结果
  winner_id TEXT,                          -- null = 平局
  rounds TEXT NOT NULL,                   -- 回合详情 JSON
  fighter_a_hp_pct INTEGER NOT NULL,      -- 甲方剩余血量百分比 (0~100)
  fighter_b_hp_pct INTEGER NOT NULL,
  created_at INTEGER NOT NULL
);

CREATE INDEX idx_arena_ind_matches_date ON arena_individual_matches (date_key);

-- 对战记录（团队赛：一场车轮战）
CREATE TABLE arena_team_matches (
  id TEXT PRIMARY KEY,
  date_key TEXT NOT NULL,
  sect_a_id TEXT NOT NULL,
  sect_a_name TEXT NOT NULL,
  sect_b_id TEXT NOT NULL,
  sect_b_name TEXT NOT NULL,
  winner_sect_id TEXT NOT NULL,
  -- 车轮战的每场 1v1 详情（JSON 数组，每个元素包含双方弟子、回合、胜负）
  duels TEXT NOT NULL,
  sect_a_kills INTEGER NOT NULL,
  sect_b_kills INTEGER NOT NULL,
  created_at INTEGER NOT NULL
);

CREATE INDEX idx_arena_team_matches_date ON arena_team_matches (date_key);

-- 奖励发放记录（防重复发放）
CREATE TABLE arena_rewards (
  id TEXT PRIMARY KEY,
  date_key TEXT NOT NULL,
  kind TEXT NOT NULL CHECK (kind IN ('daily_individual', 'daily_team', 'season_individual', 'season_team')),
  sect_id TEXT NOT NULL,
  rank INTEGER NOT NULL,
  rewards TEXT NOT NULL,                  -- {资源id: 最小单位} 的 JSON
  created_at INTEGER NOT NULL
);

CREATE INDEX idx_arena_rewards_date ON arena_rewards (date_key, kind);
```

## 7. 后端实现

### 7.1 文件结构

- `apps/server/src/modules/game/arena.ts`：纯定义与纯计算（常量、战斗模拟、奖励表、handicap 公式、战力上限计算）。不读库、不取时间、随机源通过参数注入。
- `apps/server/src/modules/game/service.ts`：在现有 service 中新增以下函数：
  - `getArena(db, userId, now)`：获取大比面板数据（报名状态、战报、排名）。
  - `setArenaLineup(db, userId, kind, discipleIds, now)`：设置出战阵容。
  - `processArenaTournament(db, now)`：定时任务 —— 12:00 结算当日比赛。
  - `processArenaSeason(db, now)`：定时任务 —— 周日额外结算赛季。

### 7.2 结算流程（processArenaTournament）

1. 判断当前 UTC+8 时间是否到了 12:00 且今天还没结算过。
2. 获取所有宗门等级 ≥ 2 的宗门（或者有弟子的宗门）。
3. 对每个宗门：
   - 查 arena_entries 看是否有今日报名记录。
   - 有 → 用玩家设置的阵容。
   - 没有 → 自动选最强 5 名可出战弟子，写入 arena_entries（auto = 1）。
4. **个人赛结算**：
   - 收集所有参赛弟子，两两配对。
   - 对每对运行 simulateArenaDuel，写入 arena_individual_matches。
   - 汇总每个弟子的胜负/积分，写入 arena_individual_scores。
   - 按积分排名发每日奖励。
5. **团队赛结算**：
   - 检查每个宗门总战力是否超限；超限的自动替换弟子。
   - 宗门两两配对，运行车轮战，写入 arena_team_matches。
   - 汇总每个宗门的胜负/积分，写入 arena_team_scores。
   - 按积分排名发每日奖励。
6. 累加到赛季表（arena_season_individual / arena_season_team）。
7. 如果是周日 → 调用 processArenaSeason 结算赛季。

### 7.3 API 路由

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | /game/arena | 获取大比面板（报名状态、今日战报、排名、赛季排名） |
| POST | /game/arena/lineup | 设置出战阵容（kind: 'individual' / 'team', discipleIds: string[]） |

### 7.4 定时任务

在 `scheduled.ts` 的 `runScheduledTasks` 中新增 `processArenaTournament(db, now)` 调用。
