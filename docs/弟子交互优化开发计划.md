# 弟子交互优化开发计划

## 0. 基线与边界

- 在独立 worktree 的 `codex/disciple-interaction` 分支实施；起点是提交 `225e44a`。主工作区有另一个 agent 的未提交改动，不能覆盖、重置或复制其文件。
- 当前分支迁移最高 `0015`；另一个 agent 正在做 `0016` 六属性/综合评分。开始编码前，等其提交并同步到本分支。保留合入后的六轴雷达和评分排序，但本轮不做评分筛选。头像框迁移预留 `0017_disciple_avatar_frame.sql`；若已有占用，取下一空号。重叠文件基于合并后的内容编辑。
- 用户现在只提供一张头像框示例，另九张尚未交付。不得复制示例、生成替代图或把占位图当成果；素材未齐时可做其他功能，但头像框视觉验收不能算完成。
- 不改战力、属性、破境、历练、招贤与结算规则；不自动提交或推送。

## 1. 详情弹窗

详情仍只存 `discipleId`，从最新 `state.disciples` 取对象；成功操作回填服务端完整 state，驱逐成功后关闭。固定紧凑的头部显示姓名、境界、头像框和状态；四个 Tab：

| Tab | 内容 |
| --- | --- |
| 概览（默认） | 雷达图、精确属性、战力、天赋、合入后已有的综合评分、简短修为摘要。雷达图必须在首 Tab。 |
| 修行 | 修为、伤势、岗位、破境胜算/消耗/操作、丹药入口。 |
| 历练 | 出发预览、倒计时、领取、此弟子的近期历练记录。 |
| 档案 | 头像框选取、私有备注、驱逐与二次确认。 |

- `DiscipleDetailDialog.vue` 内用真正的 `tablist` / `tab` / `tabpanel`，提供 `aria-selected`、方向键及 Home/End；Esc 仍只关最上层。切 Tab 保留未保存备注草稿和历练方向/时长选择，不自动写库。关闭后焦点回名册有效入口；服药二级弹窗要约束焦点在顶层。
- 弹窗只滚动当前 Tab 的内容，头部和 Tab 易于到达；桌面雷达/数值并排，手机单列；避免长说明和重复信息。检查 320px 起的宽度、长名字及危险操作确认。
- `state.journey.recent` 是**宗门最近 10 条**，不是个人完整履历。当前详情仅按 `record.discipleId === disciple.id` 展示，标题写「此弟子的近期历练」；无结果有空态。不冒称完整历史，不新增历史 API。

## 2. 名册头像快捷破境

- 保留中心姓名首字、外层进度环与独立的「详情」入口。修为数值常显，触屏无需 hover。显示/筛选只认服务端修为；本地逐秒动画与百分比四舍五入不能启用命令。
- 当 `requiredCultivation !== null && cultivation >= requiredCultivation` 时，头像成为可聚焦按钮，点击**仅打开确认弹窗**。版本上限 `requiredCultivation === null` 不显示破境入口；未满修为的头像不是假按钮。头像按钮内不得嵌套可聚焦进度条；给出可读的按钮名称及修为进度文本。
- 确认弹窗显示弟子、境界、服务端提供的胜算、灵气消耗和 `blockedReason`；失败后果用现有规则的非定量说明（消耗灵气、修为回退并进入调息），不在前端复制公式或假设服务端已有「失败后果」字段。满修为但 `canBreakthrough === false` 时可查看原因，确认按钮禁用；在外/伤势/灵气不足遵循服务端结果。取消、Esc、遮罩不提交；明确点击「确认破境」才复用既有 `/game/breakthrough` 与 App 的 Toast/state 回填。提交防重复，状态同步后即时更新资格。驱逐后关闭并恢复焦点。
- 更换头像框只在「档案」Tab 进行，不与名册头像的破境点击冲突。

## 3. 头像框数据与素材

- 10 张玩家提供的固定图片用稳定 ID `frame01`–`frame10`，固定映射到 `apps/web/public/` 资源；旧样式 ID `classic` 为旧/新弟子默认值。不要允许任意上传 URL 或路径。检查素材透明/留白的中心、尺寸与名册约 46–48px 缩放；详情可用更大预览。图片失败回退 `classic`。
- 结构：**最外进度环 → 框图 → 中心姓名首字**。中心字可读、框不遮字、环不被框覆盖。选择器为图像单选控件，显示当前选项、预览、保存/失败状态；保存后名册与详情更新，刷新/重新登录保持。
- 新迁移 `disciples.avatar_frame_id TEXT NOT NULL DEFAULT 'classic'`，SQL `CHECK` 仅允许 `classic` 和十个固定 ID。不得修改历史迁移；旧数据及旧式 INSERT 自动为 `classic`。更新 `repository.ts` 的 `DiscipleRow` 与全部显式 SELECT、私有 `view.ts`、前端类型；不扩展公开宗门、榜单、战报或招贤候选人。
- 建议接口 `POST /api/v1/game/set-disciple-avatar-frame`，请求 `{ discipleId, frameId }`，回 `{ state }`。复用严格 schema、认证/CSRF/Origin、`draftFor` → 本宗归属校验 → 单列更新 → `commitDisciple` 快照守卫。跨宗/不存在沿用 `NOT_FOUND`；非法 ID 校验失败；相同值重存不产生资源/计数/事件副作用。

## 4. 名册筛选与排序

- 现有「境界」筛选保留，增加仅在选中境界时可用的「阶段」从属筛选。阶段选项从完整弟子名单派生，按 `stage` 数值排序，显示对应 `stageName`；境界变化时清除阶段，不留隐藏条件。境界高低始终用 `realmOrder + stage`，不是名称字典序。
- 新增修为进度筛选：全部、0–不足25%、25–不足50%、50–不足75%、75–不足100%、已满但不可破、可破境、版本上限。分档为 `[0,0.25)`、`[0.25,0.5)`、`[0.5,0.75)`、`[0.75,1)`，按服务端 `cultivation / requiredCultivation` 的**原始比例**计算（例如 99.6% 仍未满），不按显示用整数百分比或本地动画。已满与可破境分别按实际门槛与 `canBreakthrough`；版本上限按 `requiredCultivation === null`。保留现有状态筛选，组合使用时文案不能混淆。
- 保留既有排序；增加境界低到高、战力低到高、修为进度高/低、修炼速度高/低。合并 0016 后保留评分**排序**，但不加评分**筛选**。修为进度跨境界按原始比例比较，版本上限排序视为 100%；并列保持原招募顺序。前端纯函数处理几十人，不加分页/新查询。
- 继续提供匹配数/总人数、重置与无结果态；筛选保留到详情操作之后。若被操作弟子不再匹配，关闭弹窗时焦点回搜索框或仍存在的入口。

## 5. 实施与验收

1. 确认工作区和 0016 合入情况、10 张素材交付；先写 `utils/discipleFilter.ts` 的纯规则与 `tests/web/disciple-filter.test.ts`，再接名册筛选/排序和常显进度。

3. 四 Tab 详情与个人历练筛选；验证草稿保留和二级弹窗键盘焦点。
4. 素材齐备后做迁移、后端接口/私有视图、前端选择与渲染。Worker/D1 测试覆盖旧数据默认、保存/重复/非法/跨宗、同步持久化、公开视图不泄露。
5. 执行 `npm run test:unit`、`npm run typecheck`、`npm run build`、`git diff --check`。浏览器核对桌面及 320/375/680px：长名字、空筛选、满环与版本上限、四 Tab、十张图片、破境确认、Esc/Tab/方向键、焦点回退。交付报告列明真实结果、素材缺项、与 0016 的集成状态及未验证视口。
