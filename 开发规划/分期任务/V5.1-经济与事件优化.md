# V5.1：经济与事件优化

三个独立改动，不需要数据库迁移。

---

## 改动一：随机事件频率提升

### 目标
把事件触发率从 0.3 次/小时提升到 2.0 次/小时，体感大约半小时一次。离线上限从 3 提到 5。

### 变更文件

**apps/server/src/modules/game/events.ts**

```ts
// 改前
export const EVENT_TRIGGER_RATE_PER_HOUR = 0.3;
export const MAX_EVENTS_PER_SETTLE = 3;

// 改后
export const EVENT_TRIGGER_RATE_PER_HOUR = 2.0;
export const MAX_EVENTS_PER_SETTLE = 5;
```

只改这两个常量，其他逻辑不动。

---

## 改动二：灵矿建筑提升灵石产出

### 目标
现有的任务堂（missionHall）改名为"灵矿"，每级 +20% 灵石基础产出速率。

### 变更文件

#### 1. packages/game-config/src/index.ts

把 missionHall 的 name 从 `'任务堂'` 改为 `'灵矿'`：

```ts
// 改前
{
  id: 'missionHall',
  name: '任务堂',
  maxLevel: 5,
  upgradeCostPerLevel: { spiritStone: '50000', ore: '10000' },
  visibility: 'public',
},

// 改后
{
  id: 'missionHall',
  name: '灵矿',
  maxLevel: 5,
  upgradeCostPerLevel: { spiritStone: '50000', ore: '10000' },
  visibility: 'public',
},
```

id 不改（`missionHall`），避免数据库里已有的建筑行 def_id 不匹配。

#### 2. apps/server/src/modules/game/constants.ts

新增常量：

```ts
export const MISSION_HALL_BUILDING_ID = 'missionHall';
export const MISSION_HALL_SPIRIT_STONE_BONUS_BP_PER_LEVEL = 2000; // 每级 +20%
```

#### 3. apps/server/src/modules/game/settle.ts

`resourceRates` 函数签名增加 `buildingLevels` 参数，灵矿等级加成灵石基础产出：

```ts
// 改前
export function resourceRates(
  config: GameConfigContent,
  disciples: readonly DiscipleState[],
): Map<string, number> {

// 改后
export function resourceRates(
  config: GameConfigContent,
  disciples: readonly DiscipleState[],
  buildingLevels?: Record<string, number>,
): Map<string, number> {
```

在函数内部，设置完 baseRatePerHour 之后、遍历弟子产出之前，加入灵矿加成：

```ts
const rates = new Map<string, number>();
for (const resource of config.resources) {
  rates.set(resource.id, Number(resource.baseRatePerHour));
}

// ── 新增：灵矿加成灵石基础产出 ──
const missionHallLevel = buildingLevels?.[MISSION_HALL_BUILDING_ID] ?? 0;
if (missionHallLevel > 0) {
  const currentRate = rates.get('spiritStone') ?? 0;
  const bonusBp = missionHallLevel * MISSION_HALL_SPIRIT_STONE_BONUS_BP_PER_LEVEL;
  rates.set('spiritStone', Math.floor((currentRate * (10_000 + bonusBp)) / 10_000));
}
// ── 新增结束 ──

// 接下来是原有的弟子岗位产出逻辑...
```

`settleEconomy` 中调用处传入 buildingLevels：

```ts
// 改前
const rateByResource = resourceRates(config, disciples);

// 改后
const rateByResource = resourceRates(config, disciples, input.buildingLevels);
```

#### 4. apps/server/src/modules/game/view.ts

`buildSectStateView` 中调用 `resourceRates` 的地方同样传入 buildingLevels：

```ts
// 改前
const resourceRatesNow = resourceRates(config, disciples.map(toDiscipleState));

// 改后
const buildingLevels = Object.fromEntries(buildings.map((b) => [b.def_id, b.level]));
const resourceRatesNow = resourceRates(config, disciples.map(toDiscipleState), buildingLevels);
```

注意：这里的 `buildingLevels` 变量可能跟下面已有的藏经阁 libraryLevel 取值重复，可以复用同一个对象（原来是 `buildings.find` 取单个值，现在统一构建一次 map 即可）。

#### 5. apps/web/src/components/SectScreen.vue

`buildingDescription` 函数中修改任务堂的描述：

```ts
// 改前
if (defId === 'missionHall') return '统筹宗门事务与弟子差遣';
```

## 改动三：采灵岗位（灵石采集）

### 目标
新增"采灵"岗位，弟子分配到此岗位后每小时产出灵石。宗门 6 级前限 1 人、6 级起限 2 人。

### 变更文件

#### 1. packages/game-config/src/index.ts

positions 数组末尾新增：

```ts
{
  id: 'stoneMining',
  name: '采灵',
  outputPerHourPerDisciple: { spiritStone: '15000' },
  visibility: 'public',
},
```

15000 最小单位 = 15 展示单位/小时/人。

#### 2. apps/server/src/modules/game/constants.ts

新增常量：

```ts
export const STONE_MINING_ASSIGNMENT = 'stoneMining';
export const STONE_MINING_LIMIT_LOW = 1;      // 6 级前
export const STONE_MINING_LIMIT_HIGH = 2;     // 6 级起
export const STONE_MINING_UNLOCK_SECT_LEVEL = 6;
```

#### 3. apps/server/src/modules/game/service.ts

`assignDisciple` 函数中，在校验岗位合法性之后、写入之前，加入人数限制：

```ts
// 在 "if (!validAssignments.has(assignment))" 之后加：
if (assignment === STONE_MINING_ASSIGNMENT) {
  const limit = Number(draft.sect.level) >= STONE_MINING_UNLOCK_SECT_LEVEL
    ? STONE_MINING_LIMIT_HIGH
    : STONE_MINING_LIMIT_LOW;
  const currentCount = draft.disciples.filter(
    (d) => d.assignment === STONE_MINING_ASSIGNMENT && d.id !== discipleId,
  ).length;
  if (currentCount >= limit) {
    throw new AppError('CAPACITY_FULL', `采灵岗位已满（上限 ${limit} 人）`);
  }
}
```

注意 `d.id !== discipleId`：如果弟子本身已经在采灵岗位，重复分配不应算占位。

#### 4. apps/server/src/modules/game/settle.ts

`resourceRates` 里的天赋匹配逻辑需要考虑采灵岗位。当前没有灵石采集天赋，所以 stoneMining 不匹配任何天赋，无需改动——现有逻辑只在 herbGathering 和 oreGathering 时给 bonus，其余岗位走默认 1.0 倍率，自然兼容。

#### 5. apps/web/src/components/SectScreen.vue 或 AssignmentSelect.vue

前端岗位选择器需要展示采灵岗位的人数限制。后端返回的 `state.assignments` 数组里会自动包含新岗位（配置驱动），但不含限制信息。

两种方案（选简单的）：

**方案 A（推荐）：后端在 SectStateView 里加限制信息**

view.ts 的 `AssignmentOptionView` 扩展：

```ts
export interface AssignmentOptionView {
  id: string;
  name: string;
  /** 该岗位当前占用人数（null = 无限制）。 */
  currentCount: number | null;
  /** 该岗位上限（null = 无限制）。 */
  maxCount: number | null;
}
```

`buildSectStateView` 中构建 assignments 时计算 stoneMining 的占用和上限：

```ts
assignments: [
  { id: IDLE_ASSIGNMENT, name: '闲置', currentCount: null, maxCount: null },
  ...config.positions.map((position) => {
    if (position.id === STONE_MINING_ASSIGNMENT) {
      const limit = Number(sect.level) >= STONE_MINING_UNLOCK_SECT_LEVEL
        ? STONE_MINING_LIMIT_HIGH
        : STONE_MINING_LIMIT_LOW;
      const count = disciples.filter((d) => d.assignment === STONE_MINING_ASSIGNMENT).length;
      return { id: position.id, name: position.name, currentCount: count, maxCount: limit };
    }
    return { id: position.id, name: position.name, currentCount: null, maxCount: null };
  }),
],
```

前端 api/game.ts 的 `SectStateView.assignments` 类型同步更新。

AssignmentSelect.vue 中，当 `maxCount !== null && currentCount >= maxCount` 且当前弟子不在该岗位时，该选项禁用，显示文案如 `采灵（1/1 满）`。
