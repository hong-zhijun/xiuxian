# V4：弟子属性、天赋与招募三选一

目标：弟子不再只有资质一个数字。新增攻击/防御/速度三个战斗属性和一个天赋，招募时展示三个候选人供选择。

前置：V3（多人互动）已完成。

天赋与岗位的对应关系：
- `herbGathering` 天赋 → 弟子在 `herbGathering` 岗位时，该弟子的产出 ×1.2

- `cultivation` 天赋 → 弟子在 `cultivating` 岗位时，修炼速度 ×1.2
- `combat` 天赋 → 战力计算时 ×1.15

## 第三节 战力公式改造

### 3.1 职责分离

- **资质（aptitude）**：只影响修炼速度（已有，不变）
- **攻击/防御/速度**：只影响战力（新增）
- **天赋**：影响对应领域的产出或战力

### 3.2 新公式

改造 `realms.ts` 的 `discipleCombatPower`：

```ts
/**
 * 单个弟子战力。
 * base = (境界序号×3 + 阶段) × 10
 * 属性加权 = (attack×0.4 + defense×0.35 + speed×0.25) / 100
 * power = base × (1 + 属性加权)
 * 战斗天赋再 ×1.15
 */
export function discipleCombatPower(
  realmId: string,
  stage: number,
  attack: number,
  defense: number,
  speed: number,
  talent?: string,
): number {
  const rIdx = realmIndex(realmId);
  const base = (rIdx * 3 + stage) * 10;
  const attrBonus = (attack * 0.4 + defense * 0.35 + speed * 0.25) / 100;
  let power = Math.floor(base * (1 + attrBonus));
  if (talent === 'combat') {
    power = Math.floor(power * 1.15);
  }
  return power;
}
```

### 3.3 影响范围

所有调用 `discipleCombatPower` 的地方都要传新参数：

1. **service.ts 的 `exploreSectRealm`**：构造 members 时加上 attack/defense/speed/talent
2. **service.ts 的 `sparWithSect`**（V3）：计算攻防双方战力时传新参数
3. **realms.ts 的 `partyCombatPower`**：members 类型加 attack/defense/speed/talent

`partyCombatPower` 的 members 类型改为：

```ts
export function partyCombatPower(
  members: { realmId: string; stage: number; attack: number; defense: number; speed: number; talent?: string }[],
): number {
  return members.reduce((sum, m) => sum + discipleCombatPower(m.realmId, m.stage, m.attack, m.defense, m.speed, m.talent), 0);
}
```

### 4.2 resourceRates 加天赋加成

当前逻辑：每个在岗弟子贡献固定产量。改为：如果弟子天赋匹配当前岗位，产量 ×1.2。

天赋→岗位映射：
- `'herbGathering'` → position id `'herbGathering'`
- `'mining'` → position id `'oreGathering'`

```ts
// 在 resourceRates 函数里，改循环：
for (const disciple of disciples) {
  const position = positions.get(disciple.assignment);
  if (position === undefined) continue;
  
  const talentMatch =
    (disciple.talent === 'herbGathering' && disciple.assignment === 'herbGathering') ||
    (disciple.talent === 'mining' && disciple.assignment === 'oreGathering');
  const bonusMultiplier = talentMatch ? 12000 : 10000; // 基点：10000=1.0x，12000=1.2x
  
  for (const [resourceId, amountText] of Object.entries(position.outputPerHourPerDisciple)) {
    const base = Number(amountText);
    const effective = Math.floor((base * bonusMultiplier) / 10000);
    rates.set(resourceId, (rates.get(resourceId) ?? 0) + effective);
  }
}
```

## 第五节 招募三选一

### 5.1 确定性随机生成器

在 `names.ts` 新增一个简单的 seeded PRNG：

```ts
/**
 * 基于种子的伪随机生成器（用于招募预览的确定性）。
 * 同一个 seed 永远产生同一序列，刷新页面重新预览不会换人。
 */
export function seededRandom(seed: string): () => number {
  let h = 0;
  for (let i = 0; i < seed.length; i++) {
    h = Math.imul(31, h) + seed.charCodeAt(i) | 0;
  }
  return () => {
    h = Math.imul(h ^ (h >>> 16), 0x45d9f3b);
    h = Math.imul(h ^ (h >>> 13), 0x45d9f3b);
    h ^= h >>> 16;
    return (h >>> 0) / 0x100000000;
  };
}
```

现有的 `randomDiscipleName`、`randomGender`、`randomAptitude` 都用 `Math.random()`。新增**带参数版本**，接受一个 `random: () => number`：

```ts
export function generateDiscipleName(random: () => number): string {
  const surname = SURNAMES[Math.floor(random() * SURNAMES.length)] ?? '云';
  const given = GIVEN_NAMES[Math.floor(random() * GIVEN_NAMES.length)] ?? '清和';
  return `${surname}${given}`;
}

export function generateGender(random: () => number): 'male' | 'female' {
  return random() < 0.5 ? 'male' : 'female';
}

export function generateStat(random: () => number): number {
  return 1 + Math.floor(random() * 100);
}

export function generateTalent(random: () => number): string {
  const talents = ['herbGathering', 'mining', 'cultivation', 'combat'];
  return talents[Math.floor(random() * talents.length)] ?? 'combat';
}
```

原有的无参版本保持不变（创建宗门初始弟子仍用 `Math.random()`，不需要确定性）。

### 5.3 生成逻辑

```ts
/** 根据宗门当前状态生成 3 个确定性候选人。 */
export function generateCandidates(sectId: string, dateKey: string, recruitCount: number): RecruitCandidate[] {
  const seed = `${sectId}:${dateKey}:${recruitCount}`;
  const random = seededRandom(seed);
  const candidates: RecruitCandidate[] = [];
  for (let i = 0; i < 3; i++) {
    const talent = generateTalent(random);
    candidates.push({
      name: generateDiscipleName(random),
      gender: generateGender(random),
      aptitude: generateStat(random),
      attack: generateStat(random),
      defense: generateStat(random),
      speed: generateStat(random),
      talent,
      talentName: findTalent(talent)?.name ?? talent,
    });
  }
  return candidates;
}
```

### 5.4 两个端点

**GET /game/recruit-preview**（只读，不写库）：

1. 读宗门快照（不做结算 — 与排行榜同理，预览不该有副作用）
2. 检查是否能招募（次数/上限/资源），返回 `canRecruit` 和 `blockedReason`
3. 用 `generateCandidates(sectId, dateKey, recruitCount)` 生成 3 个候选人
4. 返回 `{ candidates, canRecruit, blockedReason, cost }`

**POST /game/recruit** body 改为 `{ choice: 0 | 1 | 2 }`：

1. 读快照 + 结算（draftFor）
2. 检查次数/上限/资源（与原逻辑一致）
3. 用同样的 `generateCandidates(sectId, dateKey, recruitCount)` 生成候选人
4. 取 `candidates[choice]` 作为选中弟子
5. 扣资源 + 创建弟子 + 更新招募计数
6. 返回 `{ state, outcome: { discipleName, aptitude, attack, defense, speed, talent } }`

## 第十节 验收标准

1. `npm run typecheck && npm run build` 通过
2. `npm run dev` 启动后：
   - 创建宗门后初始弟子有随机攻/防/速和天赋
   - 弟子卡片上能看到攻击/防御/速度数值、天赋名称、战力值
   - 点击「张榜招贤」弹出 3 个候选人（各有不同属性/天赋），选一个入门
   - 刷新页面重新打开招贤弹窗，候选人不变（同一次机会的候选人固定）
   - 招募完成后下一次打开看到新的 3 个候选人
   - 有采药天赋的弟子放在采药岗，产量比无天赋的高
   - 有修炼天赋的弟子修炼速度更快
   - 有战斗天赋的弟子在秘境和切磋里战力更高
   - 秘境探索和切磋用新公式（attack/defense/speed），不再用 aptitude 算战力
3. 不做：装备系统、技能系统、属性成长/洗练、多天赋
