# V3：多人互动（排行榜 + 公开档案 + 切磋）

目标：让 3~5 个朋友之间能看到彼此、比较进度、简单互动。没有实时匹配、没有掠夺、没有自由文本。

前置：V2-1（宗门升级）和 V2-2（秘境探索）已完成。

## 第二节 排行榜

### 2.1 排行维度

只做一个综合榜，按以下优先级排序（3~5 人不需要分页）：

1. 宗门等级 DESC
2. 声望 DESC
3. 创建时间 ASC（先建的排前面）

```ts
  return this.all<SectRow>({
    sql: `SELECT id, user_id, name, level, vein_level, reputation, last_settled_at,
```

1. 查所有宗门（`findAll`）
2. 对每个宗门查弟子列表（用 `DiscipleRepository.findBySectId`）
3. 找出每个宗门境界最高的弟子（用 `realmIndex` 比较，同境界取 stage 最高，再同 stage 取资质最高）
4. 组装返回

## 第四节 切磋系统

### 4.1 规则

- 每日总共 5 次切磋机会（UTC+8 自然日重置），同一目标宗门每日只能打 1 次
- 各选 1 名弟子（攻方自选，防方也选对方可见的弟子）
- 受伤弟子不能出战（攻方检查；防方不检查受伤状态，因为不影响防方弟子）
- 战力计算复用 `discipleCombatPower`（realms.ts），加随机浮动 ±15%
- 攻方战力 > 防方战力：胜利，+10 声望，奖励灵石 5000（最小单位）
- 攻方战力 < 防方战力：失败，无奖励
- 攻方战力 == 防方战力：平局，无奖励
- 不能切磋自己的宗门

### 4.2 战力浮动

```ts
// 实际战力 = basePower * (0.85 + Math.random() * 0.30)
// 即 basePower 的 85%~115%
function fluctuatedPower(basePower: number): number {
  return Math.floor(basePower * (0.85 + Math.random() * 0.30));
}
```

### 4.3 后端

**路由**：`POST /game/spar`

**schema.ts 新增**：


**service.ts 新增**：`sparWithSect(db, userId, targetSectId, myDiscipleId, targetDiscipleId, now)`

校验流程：
1. 读自己的宗门快照（draftFor）
2. 按 id 读目标宗门（findById），不存在抛 NOT_FOUND
3. 不能打自己：`targetSect.id === draft.sect.id` → 抛 VALIDATION_ERROR
4. 每日总次数检查：查 sparring_log 今日攻方次数 >= 5 → 抛 DAILY_LIMIT
5. 每日同目标检查：查 sparring_log 今日攻方 vs 该防方 >= 1 → 抛 DAILY_LIMIT
6. 攻方弟子存在性 + 不在受伤中
7. 防方弟子存在性（不检查受伤）：`DiscipleRepository.findById(targetDiscipleId)`，验证该弟子属于目标宗门
8. 算战力 + 浮动 → 判定胜负
9. 胜利时：`draft.sect.reputation += 10` + 灵石 +5000，写 UPDATE sects SET reputation
10. 写入 sparring_log
11. `draft.commit()` 返回 state + 切磋结果

**repository.ts 新增**：

```ts
export interface SparringLogRow {
  id: string;
  attacker_sect_id: string;
  defender_sect_id: string;
  attacker_disciple_id: string;
  defender_disciple_id: string;
  attacker_power: number;
  defender_power: number;
  result: string;
  reputation_gained: number;
  created_at: number;
}

export class SparringRepository extends ParamRepository {
  async countTodayByAttacker(sectId: string, dayStartMs: number): Promise<number> {
    const row = await this.one<{ total: number }>({
      sql: 'SELECT COUNT(*) AS total FROM sparring_log WHERE attacker_sect_id = ? AND created_at >= ?',
      params: [sectId, dayStartMs],
    });
    return Number(row?.total ?? 0);
  }

  async countTodayByPair(attackerSectId: string, defenderSectId: string, dayStartMs: number): Promise<number> {
    const row = await this.one<{ total: number }>({
      sql: 'SELECT COUNT(*) AS total FROM sparring_log WHERE attacker_sect_id = ? AND defender_sect_id = ? AND created_at >= ?',
      params: [attackerSectId, defenderSectId, dayStartMs],
    });
    return Number(row?.total ?? 0);
  }
}

export function insertSparringLogStatement(row: {
  id: string;
  attackerSectId: string;
  defenderSectId: string;
  attackerDiscipleId: string;
  defenderDiscipleId: string;
  attackerPower: number;
  defenderPower: number;
  result: string;
  reputationGained: number;
  now: number;
}): ParameterizedQuery {
  return {
    sql: `INSERT INTO sparring_log (id, attacker_sect_id, defender_sect_id, attacker_disciple_id,
            defender_disciple_id, attacker_power, defender_power, result, reputation_gained, created_at)
          VALUES (?, ?, ?, ?, ?, ?, ?, ?, ?, ?)`,
    params: [row.id, row.attackerSectId, row.defenderSectId, row.attackerDiscipleId,
             row.defenderDiscipleId, row.attackerPower, row.defenderPower,
             row.result, row.reputationGained, row.now],
  };
}

export function updateSectReputationStatement(sectId: string, delta: number): ParameterizedQuery {
  return {
    sql: 'UPDATE sects SET reputation = reputation + ? WHERE id = ?',
    params: [delta, sectId],
  };
}
```

### 4.4 声望写入细节

切磋的声望和灵石奖励通过 `draft.addStatement` 追加到 batch：

```ts
if (result === 'win') {
  draft.addStatement(updateSectReputationStatement(draft.sect.id, 10));
  draft.addStatement(resourceDeltaStatement(draft.sect.id, 'spiritStone', 5000, now));
  // 更新内存状态供 view() 使用
  draft.sect.reputation = (Number(draft.sect.reputation) || 0) + 10;
  draft.balances = draft.balances.map(row =>
    row.resource_id === 'spiritStone'
      ? { ...row, balance: Number(row.balance) + 5000, updated_at: now }
      : row,
  );
}
```

注意：SectRow 接口要加 `reputation: number` 字段。sect.reputation 在 draft 上直接改内存值，commit 时 batch 写入。SectDraft 不需要结构性变更——声望不参与结算，只是追加 statement。

## 第七节 验收标准

1. `npm run typecheck && npm run build` 通过
2. `npm run dev` 启动后：
   - 排行榜能看到所有已创建的宗门，按等级和声望排序
   - 点击其他宗门能看到公开档案（弟子、建筑），看不到资源余额
   - 选弟子切磋，胜利获得声望和灵石，失败无惩罚
   - 每日 5 次总限 + 同目标 1 次限制生效
   - 不能跟自己切磋
   - 受伤弟子不能作为攻方出战
   - 宗门顶栏显示声望值
3. 不做：实时匹配、掠夺资源、自由文本留言、装备系统、阵容布阵
