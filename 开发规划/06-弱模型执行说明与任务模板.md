# 弱模型执行说明与任务模板

## 1. 任务粒度

一次一个任务卡。大任务允许拆为 ID-a 数据契约、ID-b 纯函数、ID-c 服务接口、ID-d 页面、ID-e 验证；保持父任务未完成直到全部通过。

部署目标固定Cloudflare：Vue + Pages（前端）、Workers/Hono + D1（后端）、Wrangler。Docker不在开发前置中；不安装PostgreSQL，不启动常驻Node后端；统一使用02的D1 batch/版本断言封装。

优先纵向交付可验证能力；不先写几十张表和全站空页面。除文档明确要求，不自行加新框架、服务或玩法。

## 2. 固定执行流程

1. 阅读根目录 AGENTS（若后续存在）、对应任务、02/03/04 相关章节和进度记录。
2. 核对前置任务、当前工作树、现有目录和可运行命令；已有代码优先复用，不重建项目。
3. 列出本次改动范围、验收点、是否需要迁移；发现规则冲突先记录。
4. 先为纯逻辑/事务不变量写测试或给出可执行用例，再做最小实现。
5. 接真实 API 和权限，补前端加载/空/失败状态；不拿 mock 代替完成。
6. 跑最相关测试，然后类型、lint、构建及必要回归；失败要修，不隐藏。
7. 更新进度、运行说明和契约；列出实际证据、残留问题、下个任务，不擅自继续下期。

无法访问环境/依赖时记录具体阻塞，可做不依赖它的工作；不得把“没跑”改写成“应该通过”。

## 3. 单任务开发提示词

```text
你正在实现修仙宗门挂机文字游戏。

本次只执行：<P1-03>。
任务卡：开发规划/分期任务/<对应阶段文件>。
必须遵守：开发规划/02、03、04、05、06 的相关规则，及已确认决策。

请先检查前置任务完成证据、现有代码和工作树，再简述实现范围。
不要更换技术栈，不要重建已有项目，不要顺手做下一任务。
涉及数值/随机/奖励只由服务端处理；所有写入复用事务和幂等基础。
修改范围限定在任务卡指定模块及必要测试、迁移、契约和文档。

完成后：
1. 列出真实修改文件及功能。
2. 逐条给出任务卡验收结果。
3. 给出运行过的命令、成功/失败与关键输出。
4. 明确未执行项和风险，不伪造截图/测试结果。
5. 更新开发规划/07-进度与决策记录.md。
6. 停在本任务边界，等待评审。
```

## 4. 评审提示词

```text
只评审任务 <ID>，先不要改代码。
对照任务卡、领域规则与测试门禁检查 diff 和实际测试。
重点找：重复结算/奖励、事务部分提交、越权、溢出、错误状态、旧浏览器、迁移丢数据。
按严重性列出可定位的文件/行号、复现条件、预期行为和建议测试。
未发现问题时明确说明验证范围及未验证部分，不只说“看起来正常”。
最后给出：通过 / 需修改 / 环境阻塞；下一阶段是否允许开始。
```

评审与开发最好用不同会话，提供 git diff 或提交范围；不依赖原会话记忆。没有独立评审条件时至少清理上下文后对照证据复查。

## 5. 故障修复提示词

```text
修复任务 <ID> 的这一项失败：<错误信息/复现步骤>。
保持已确认契约不变，不重写无关模块。
先定位根因并补回归测试，再做最小修复。
重新运行原失败用例及相邻回归；记录命令与结果。
若根因需要变更领域规则，暂停该变更并提交明确决策问题。
```

## 6. 禁止行为

- 前端算余额、用 localStorage 当正式存档、客户端传随机种子/奖励。
- 用 setInterval 每秒遍历全服推进；用内存定时器替代持久队列。
- 用普通SQLite驱动或mock冒充D1绑定集成验收；本地须workerd/D1，发布前关键用例须staging远程D1。
- 先扣款提交、后发货提交；将一次资产命令拆成多个D1 batch；UPDATE影响0行后仍继续无条件发奖。
- GET 扣费用、重播再发奖、重试重新掷骰。
- 将测试开关开放到生产；通过删除失败测试过门禁。
- 用“TODO”“待接接口”“演示数据”冒充完成的业务。
- 重置用户数据、回滚他人改动、未授权强推或擅自上生产。
- 将未验收的阶段标记完成；把延期范围默默删掉。

## 7. 交接格式

```text
任务 ID：
状态：待验收 / 完成 / 阻塞
前置版本或提交：
改动文件：
实现范围：
迁移/配置变化：
测试命令与关键结果：
验收证据路径：
未执行项及原因：
已知风险/新决策：
建议下一任务：
```

证据保存 `docs/verification/<任务ID>/`；不要提交含密码/token 的日志。模型自测完成先标待验收，评审通过后才标完成。
