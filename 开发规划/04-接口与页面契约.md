# 接口与页面契约

## 1. HTTP 公约

- 前缀 `/api/v1`，JSON，UTF-8；同源 Cookie session；客户端不可指定当前 userId，sectId 由 session+server 决定。
- GET 只读，不结算、不扣次数；玩家进入游戏用 POST `/sect/sync` 结算并取得快照，后台每 60 秒至多一次，隐藏标签页停止轮询。
- 除登录/退出等账号动作外，所有游戏 POST/PATCH 必须带 `Idempotency-Key` 与 CSRF token。重试沿用原 key，新意图创建新 key。
- 登录/注册使用同源Origin与JSON校验，成功后取得session/CSRF token；退出仍需CSRF。账号接口不要求游戏幂等键，注册靠账号唯一约束，退出重复调用也保持已退出。
- 幂等作用域 = userId + method/path + key；请求摘要不符返回冲突。保留至少 7 天；客户端不能自动重试超过 7 天的旧命令。事件、订单、任务、奖励另有永久业务唯一约束。
- 读取一致快照后固定serverNow，先验证归属再计算；D1 batch内断言快照版本与必要截止条件；冲突重试时刷新时间，不能按客户端时间裁决。
- API资源金额使用十进制字符串，普通计数/基点用JSON number；D1入参转安全整数，不能把BigInt直接传给D1。
- GET 列表 cursor 分页，默认 20、最多 100；服务端生成 opaque cursor，稳定 createdAt+id 或榜单稳定排序键。
- 写响应返回受影响 stateVersion 与必要快照；浏览器只接受不旧于当前缓存的版本，防止乱序响应覆盖新状态。
- 业务错误不能自动循环重试；网络中断最多重试 2 次并保持 key，之后明确“结果待确认”，通过查询或原 key 恢复。

```typescript
type ApiResponse<T> =
  | { ok: true; data: T; requestId: string; serverTime: string }
  | { ok: false; error: { code: string; message: string;
      details?: Record<string, unknown> }; requestId: string; serverTime: string };

type ResourceView = {
  type: 'spiritStone' | 'spiritualEnergy' | 'herb' | 'ore';
  amount: string; capacity: string; ratePerHour: string;
};

type SectSnapshot = {
  id: string; serverId: string; name: string; level: number;
  veinLevel: number; reputation: number; stateVersion: number;
  lastSettledAt: string; offlineCapSeconds: number;
  resources: ResourceView[]; disciples: DiscipleSummary[];
  buildings: BuildingSummary[]; availableActions: ActionAvailability[];
};
```

以上类型是规划摘要；P0/P1 必须补齐 DiscipleSummary、BuildingSummary、ActionAvailability 的真实 schema。disabledReason 由服务器返回，前端不可仅靠是否灰色进行安全判断。

sync 响应另含 settlement：from、economicEnd、settledTo、creditedSeconds、discardedSeconds、资源接受量/溢出量、修为变化、完成任务摘要。它是已到账总结，不是再点一次领取；只展示一次也不影响资产。

## 2. 错误契约

| HTTP | code | 前端行为 |
| --- | --- | --- |
| 400 | VALIDATION_ERROR | 字段错误，不清空全部表单 |
| 401 | UNAUTHENTICATED | 跳登录，保留返回路由 |
| 403 | FORBIDDEN / CSRF_INVALID | 禁止重试扣费操作，刷新鉴权状态 |
| 404 | NOT_FOUND | 包括不可见的他人私有对象，避免枚举 |
| 409 | IDEMPOTENCY_CONFLICT / STATE_CONFLICT | 同 key 不同请求或状态变化；同步后重选 |
| 409 | INSUFFICIENT_RESOURCE / CAPACITY_FULL | 显示缺少数量或容量 |
| 409 | INVALID_STATUS / COOLDOWN_ACTIVE / DAILY_LIMIT | 显示状态、服务器剩余时间或次数 |
| 410 | EXPIRED | 清理过期操作入口 |
| 429 | RATE_LIMITED | 尊重 Retry-After，不自动密集重试 |
| 500/503 | INTERNAL_ERROR / TEMPORARILY_UNAVAILABLE | 通用提示和 requestId，不暴露堆栈 |

错误码与状态码在 contracts 中集中定义；同一场景不能不同页面各发一套中文字符串。

## 3. P0/P1 接口

表中路径省略 `/api/v1`。所有 body 都采用严格 schema，不接受未声明字段。

| 方法/路径 | 输入 | 输出/限制 |
| --- | --- | --- |
| GET /health/live、/health/ready | 无 | 存活/数据库迁移就绪，不泄露连接信息 |
| POST /auth/register | account,password,inviteCode | 注册开关；不返回 passwordHash |
| POST /auth/login | account,password | 设置 Cookie，返回 user 摘要和 csrfToken |
| GET /auth/me | 无 | user、当前宗门摘要、csrfToken；未登录 401 |
| POST /auth/logout | CSRF | session 失效 |
| GET /config/public | version 可选 | 只给已允许公开的定义，不含事件暗奖/RNG |
| POST /sects | name,serverId | 一账号同服仅一宗门，初始化完整快照 |
| POST /sect/sync | 空 body | SectSnapshot + settlement |
| GET /sect | 无 | 已存快照，只读、可能尚未同步 |
| POST /sect/upgrade | expectedLevel | 新宗门等级/上限/成本变化 |
| POST /sect/vein/upgrade | expectedLevel | 新灵脉与最终产量 |
| GET /disciples、/disciples/:id | cursor 或 id | 仅本人；详情含速率来源、概率、可行动作 |
| POST /disciples/recruit | 空 | 新弟子/成本/今日次数 |
| POST /disciples/:id/assignment | assignment,targetId? | 归属/岗位容量/互斥验证后快照 |
| POST /disciples/:id/breakthrough | pillItemDefId? | 丹药模板ID，可选；服务端消耗1份；一次随机 |
| POST /buildings/:id/upgrade | expectedLevel | 先结算旧等级，返回新快照 |
| GET /chronicles | cursor,type? | 本宗史册 |

expectedLevel 用于挡过时界面重复升级，不替代锁与幂等。

## 6. 页面和垂直流程

| 页面 | 阶段 | 核心操作及必须有的状态 |
| --- | --- | --- |
| 登录/建宗门 | P0/P1 | 输入错误、注册关闭、重复宗门、session 失效 |
| 宗门总览 | P1 | 资源/容量/净产量、挂机摘要、待办、断线、空状态 |
| 弟子列表/详情 | P1 | 筛选、派工、速率/突破概率/成本、满员/受伤/冷却 |
| 建筑 | P1/P2/P6 | 等级/成本/效果前后对比、未解锁、管理岗位 |
| 背包/功法/炼制 | P2 | 绑定、数量、装备槽、队列、容量不足 |
| 历练/阵容/战报 | P2 | 解锁条件、前后排、重复成员、战报快进/重播 |
| 事件/关系/人生/史册 | P3 | 条件不足、已过期、确认、筛选、分页 |
| 世界/公开档案/切磋/排行榜 | P4 | 隐私设置、快照过时、重复挑战、周期更新时间 |
| 坊市/我的订单 | P5 | 总价/手续费、买前确认、抢单失败、到期/售出 |
| 妖兽/贡献/灵兽 | P6 | 活动未开/结束、HP 刷新、剩余次数、邮件领奖 |

禁止用前端假数据演示代替真实 API；开发 fixtures 必须只在开发模式开启。每期只露出已实现导航，未来功能不开空按钮。

用户关键路径：登录 → sync → 看挂机摘要 → 处理完成任务 → 调岗位/养弟子 → 投资源 → 可选多人 → 下线。总览可直接抵达待处理内容，不要求逐页找红点。
